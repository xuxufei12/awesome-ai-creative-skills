Remotion + Claude Code 的完整生产流程

## Collected text / 收录正文

````text
【第二步:搭环境】
工具:Claude Code(当 Agent)+ Remotion(用 React 做视频的框架)+ FFmpeg(检查和处理素材)。先装好 Node.js、Claude
Code、FFmpeg,然后:
npx create-video@latest --yes --blank motion-studio
cd motion-studio
npx remotion skills add
npm run dev
再开一个终端进 motion-studio 目录启动 Claude Code,模型选 Opus 5.5。
目录里放:CLAUDE.md(每次都要遵守的规则)、BRIEF.md(这条片子的简报)、STYLE.md(视觉方向)、STORYBOARD.md(分镜),
public 里放 logo、截图、字体、音频,reviews 里放评审用的帧图和 findings.md,out 里放预览和成片。
【第三步:给 Bot 一本"永久操作手册"(提示词 1)】
让 Claude 创建 CLAUDE.md,核心规则(意译):
- 没有分镜之前不许动手实现
- 只能用你给的真实素材,不许编造界面、数据、好评或产品功能
- 每个动画都由帧号或确定的时间驱动
- 全片只用一种主视觉方向,没有表达目的的东西不要动
- 先渲染几张代表帧,再渲染整条
- 要看渲染出来的结果,不能只看代码
- 问题尽量局部修复,保留全部可编辑源码
禁止项:泛滥的渐变背景、过度弹跳、发光粒子、看不清的字、假的产品看板、没有目的的镜头运动。
一句话:MP4 存在不等于完成,满足简报和验收要求才算完成。
【第四步:让导演写简报(提示词 2)】
告诉它:项目是什么(比如一个效率 App 的发布片)、核心信息(把乱糟糟的项目板变成清晰的冲刺计划)、受众(创始人、产品
团队、开发者)、时长 20 秒、要三个版本(16:9 主版、9:16 竖版、1:1 方版)、必须用你放在 public 里的截图/logo/字体,
不许造假界面。让它检查素材、列出缺什么、写 BRIEF.md、定中心视觉创意、写故事结构、解释每个场景为什么存在。关键一
句:先别写动画代码,等我批准。
【第五步:把参考变成视觉身份(提示词 3)】
让它扮演美术指导,看你放进 references 文件夹的图和视频,提取:字体气质与字重层级、构图与留白、颜色与对比规则、动
效节奏(入场、落定、停留)、质感(颗粒、阴影、边框)。结果存进 STYLE.md。注意写明"不要照抄具体构图、作品和品牌,要
为我们的产品做出自己的方向",先给我看方案再动手。
【第六步:把故事变成可编辑的时间线】
作者的 20 秒示例分五场:问题(0‒3 秒,杂乱的任务板进场)→ 动作(3‒7 秒,光标选中整理功能)→ 转变(7‒11 秒,任
务重新排成清晰优先级)→ 结果(11‒16 秒,整齐的冲刺计划落定,停够时间让人看懂)→ 收尾(16‒20 秒,产品名、logo、
行动号召)。按 30 帧每秒,20 秒就是 600 帧。模型写的是动画代码(用 Remotion 的 spring、interpolate 控制位移和缩
放),不是最终视频。
【第七步:渲染工程师先出"静帧",别直接出整片(提示词 4)】
让它读三份文档,渲染前先确认分辨率、帧率、时长、字体能加载、素材都在,再渲染代表静帧和一小段低成本预览。命令示
例:
mkdir -p out/previews
npx remotion still Launch out/previews/opening.png --frame=30
(再出 action 第 150 帧、result 第 390 帧、closing 第 570 帧)
预览只渲染互动区间:npx remotion render Launch out/previews/interaction.mp4 --frames=90-330 --codec=h264
这里 Launch 是示例里的合成 ID,换成你自己项目的。预览通过之前,不许渲染最终成片。
【第八步:评审必须独立,动画师不能给自己打分(提示词 5)】
最容易被忘的部门。渲染成功只证明文件存在,不证明好看。最好开一个全新上下文,只给原始简报和渲染帧,让它当评审:给
构图、字体、产品可读性、动效质量、节奏、连贯性、品牌一致性各打 1‒10 分,挑出三个最大问题,每个问题写清:帧号或时
间点、看到了什么、为什么影响效果、最小修复方案、哪些必须保留。报告存成 reviews/findings.md。把"让它更专业一点"这
种空话,变成"第 210 帧光标压住了结果标签,把光标提前移走"这种工程任务。静帧看版式缺陷,视频看节奏和转场,两个都要
看。
【第九步:修复循环要有停止规则(提示词 6)】
流程:动画 → 渲染预览 → 评审 → 通过就交付,不通过就按具体问题局部修复 → 再渲染 → 再评审。规则:每个缺陷找最
小改动、保留已批准的决定、只渲染受影响的帧、检查相邻场景的衔接,每个缺陷最多修两轮,两轮还不行就停下说明卡点、请
人拍板;绝不为了过评审而删掉验收要求。
【第十步:一条片子出三个版本,别只裁剪】
同一个故事,横版可以产品和标题并排,竖版要先出标题再让界面铺满。让 Agent 为 16:9、1:1、9:16 分别做版式,每个版本
单独出静帧、单独评审。交付物不只是三个 MP4,还要有海报帧、可编辑源码、素材、联系表和说明。
【第十一步:留下工作室,换项目】
把样式规则、可复用组件、动画方法、评审清单、渲染命令都留下来,下次只换项目内容。评审反复发现"标题消失太快",就
把"必须有阅读停留时间"写进规则,以后每条片子自动继承。第一条片子要搭环境、反复试;第二条可以复用场景架构和质检流
程;第三条还能带上前两条踩过的坑。
【第十二步:存成 Skill(提示词 7)和总提示词】
第一个项目过审后,让 Claude 创建名为 motion-studio 的技能:目的是把批准的创意简报变成专业的代码渲染视频;流程是导
演→美术→动画→渲染→评审→交付;规则是不编造素材、不跳过创意批准关卡、不批准没检查过的输出、修复保持局部、限制
反复修复次数、保存所有重要产物;输出是成片、海报帧、联系表、可编辑源码、素材、评审报告。之后用总提示词开工:填入
产品名、网址、受众、一句话核心信息,七个阶段(导演→美术→动画→渲染→评审→修正→交付)依次走,重大创意决定和发
布前一律停下来等你批准。
````

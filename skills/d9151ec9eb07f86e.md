# DeepSeek 生图 (deepseek-imagegen)

让 DeepSeek 驱动的 agent 拥有图像生成能力：把用户提供的文章、描述或一句话，提炼为一张高质量的位图（封面、插画、概念图、海报素材等），保存到输出目录，并留存 prompt 记录以便复现和二次修改。

核心目标：**少问问题，直接产出一张能用的图**。图必须有明确视觉隐喻、强构图；若生成封面类图片，需给标题留出干净的中部左侧或中部右侧负空间。

## 原理

- DeepSeek 官方模型本身不提供图像生成 API。
- 本 Skill 通过 **Apimart 图像 API**（默认模型 `gpt-image-2`）完成出图：skill 负责"怎么想"（提炼主题、构图、写 prompt），`scripts/image_gen.py` 负责"怎么画"（调 API、轮询、下载）。
- API Key 从环境变量 `APIMART_API_KEY` 或 `--api-key` 参数读取，脚本不写死密钥。获取：https://apimart.ai/keys

## 输入

支持以下输入形式：

- 用户直接描述画面：一句话、一段描述、或粘贴文章/段落/摘要。
- 用户提供本地文件路径（`.md`、`.txt`、`.docx`、`.pdf`）。能读取则读取全文；文件过长则读取标题、开头、结尾和关键小标题。
- 用户给出风格要求，例如"赛博朋克""极简""电影感""手绘风""像电影海报"。
- 用户给出尺寸要求，例如"16:9 横版""9:16 竖版""1:1 方图"。

## 默认输出

- 默认尺寸：`16:9`（用户可指定其他比例，如 `1:1`、`9:16`、`4:3`）
- 默认保存位置：`./output/`（可通过修改 SKILL.md 或设置 EXTEND.md 中的 `default_output_dir` 自定义）
- 默认文件名：`img-{slug}-{YYYYMMDD-HHMMSS}.png`
- 同时保存提示词记录：`img-{slug}-{YYYYMMDD-HHMMSS}.prompt.md`

文件名 slug 用主题的 2-4 个英文或拼音/kebab-case 词，避免中文路径兼容问题。

## 工作流

### 1. 读取和提炼内容

快速完成以下判断，不要输出长篇分析：

1. 用户想要的核心画面/核心隐喻是什么。
2. （若涉及标题文字）主标题：中文优先，少于 10 个汉字；英文少于 6 个词。
3. （若涉及标题文字）副标题：一句短句，不超过 18 个汉字。
4. 视觉主体：一个具体画面，避免把抽象概念做成泛泛的科技背景。
5. 构图策略：二选一。
   - 视觉重心在右侧 2/3，左侧 1/3 留白（放文字或留呼吸感）。
   - 视觉重心在左侧 2/3，右侧 1/3 留白（放文字或留呼吸感）。

### 2. 简短确认文本

在生成前，向用户简短展示：

```markdown
画面：[一句话描述视觉主体]
构图：[左侧留白/右侧留白]
尺寸：[16:9 / 9:16 / 1:1 / 其他]
```

如果用户明确说"直接生成""不用确认""按默认出图"，展示上述四行后直接继续生成，不再等待确认。请求已经很明确时，只做一次轻量确认，不要进入复杂问卷。

### 3. 构造并保存完整图片提示词

在调用图片后端前，必须先把最终 prompt 保存到输出目录的 `.prompt.md` 文件。这个记录用于复现和二次修改。

Prompt 必须包含以下结构：

```text
Aspect Ratio: [16:9 / 9:16 / 1:1 / 用户指定].
Resolution: [1920 × 1080 或对应比例].

Composition: [明确说明视觉重心在左/右侧 2/3，另一侧 1/3 是干净负空间；如有文字，标题渲染在该区域。]

Subject: [基于用户需求的具体视觉画面，写清主体、场景、光线、材质。]

Text Rendering: （仅当用户需要画面中带文字时）Render the following text directly in the image, as part of the artwork (not overlay, not watermark):
- Main Title (主标题): "[主标题内容]" — placed in the negative space area, large size, bold, high contrast.
- Subtitle (副标题): "[副标题内容]" — placed below or beside the main title, smaller size.
The text must be rendered natively in the image, properly kerned, no distorted characters, no misspellings. Chinese characters must be correct and complete.

Style: cinematic lighting, high-detail material texture, strong visual hierarchy, premium editorial aesthetic, 8k detail. The title text should look like it belongs to the artwork, not like a post-production overlay.

Prohibit: No extra random words, no logos, no watermarks, no UI screenshots, no decorative captions outside the specified text. No text at the very top edge or very bottom edge — only in the designated negative space area.
```

中文用户给中文描述时，标题保持中文，视觉描述尽量用英文表达，通常更利于图像模型理解。

### 4. 调用图片生成后端

优先使用本 Skill 自带的脚本：

```bash
python "{script_path}" --prompt-file "{prompt-file}" --output "{output-dir}/img-{slug}-{timestamp}.png" --size "{size}" --resolution "1k" [--api-key "$APIMART_API_KEY"]
```

脚本路径检测顺序：
1. `{skill-dir}/scripts/image_gen.py`（Skill 自带，开箱即用）
2. 用户自定义路径（若通过 EXTEND.md 或环境变量显式指定了脚本位置，则优先使用该路径；未指定时始终使用 Skill 自带脚本）

`--api-key` 可省略：脚本会读取环境变量 `APIMART_API_KEY`。如果两者都没有，脚本会给出获取指引后退出，此时保留 prompt 文件并告知用户缺少 Key。

如果脚本不可用，按以下降级顺序尝试：
- 用户在当前请求指定的其他后端
- 运行时原生图像工具（如 Codex imagegen）
- 已安装的其他非原生后端

降级时仍需保持约束：尺寸符合用户要求、输出到指定目录、先保存 prompt 文件、生成位图文件。

如果没有任何可用图片后端，告诉用户缺少后端，并给出已保存的 prompt 文件路径。

### 5. 完成反馈

生成完成后，只输出必要信息：

```markdown
已生成图片：{输出目录}\img-xxx.png
提示词记录：{输出目录}\img-xxx.prompt.md
```

如果生成失败，保留 prompt 文件，并简短说明失败原因和下一步建议。

## 质量规则

- 画面必须从用户需求中抽出具体隐喻，不做通用 AI 科技感背景。
- 需要文字时，文字空间必须在画面中部左侧或中部右侧，不能贴顶部或底部。
- 构图要主动创造负空间，而不是生成完再"假装能放字"。
- 标题短、有张力；副标题提供解释或补充。
- 默认只生成一张，除非用户明确要求多版。

## 修改请求

用户如果说"换个风格""标题不对""文字放右边""重新生成一版"，读取上一次的 `.prompt.md` 或沿用本轮上下文，只改用户指出的部分，然后保存新的 prompt 和图片到输出目录。不要覆盖旧文件。

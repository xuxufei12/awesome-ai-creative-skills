# video-char-mv

Turn a real photo (e.g. of your own child) or a character brief into a 3D Pixar-style cartoon character, then generate an original, heart-warming vertical music video (autumn / the seasons / small everyday joys, set to one song, bold subtitles with keywords in yellow). Runs locally at zero cost, ready for Douyin. Flow - photo → FLUX.2 klein makes 3 character designs for the user to pick → for each shot, draw a first frame and a last frame using the design as reference → local 5B first/last-frame image-to-video → two-pass colour grading → frame interpolation to 60 fps → cuts timed to the song's lyrics → subtitles + music → automatic QC. Triggers - turn this photo into a cartoon, animate my kid, emma, heart-warming cartoon video, cartoon character MV, /video-char-mv.

# Photo → cartoon character → heart-warming MV (local, zero cost)

All commands run from the repo root. `python` below means a Python 3.11+ environment with numpy / opencv / pillow (e.g. a conda env).

This flow was confirmed by the user on its first episode (kid01, "emma's Autumn"): pictures, character and subtitles are all original. The core generation method is **first/last-frame** video: we draw both the first and last frame of every shot ourselves, and the model fills in the motion between them.

## Red lines

- **The real photo is used only to design the cartoon character; the real photo and real face never appear in the video.** Only use photos of the user themselves or a child in their care — never other people's children
- No brand marks (the swoosh on shoes, toy tags). Put `plain white sneakers with no logos` and `plush toy with no tag` in the prompt
- Pictures, character and subtitles are original; **never use frames from someone else's video** (at most borrow colour statistics as a grading reference)
- Music: a local preview may use any song, but **at publish time search for the song in the platform's music picker and use the library version**. Never upload a video with someone else's audio baked in (audio fingerprinting flags it as re-uploaded content)
- Children: only warm everyday content; no dangerous actions (heights, alone in water, fire)
- Tell the user how long a long task will take; if they want to see the result first, make a 5-second preview first; quit Chrome and keep the lid open while generating

## Step 1: character design (about 3 minutes)

Put the photo at `characters/<name>/photo.png` (personal photos stay local — never commit them) and have FLUX.2 [klein] 4B make 3 versions for the user to choose from:

```bash
draw-things-cli generate --local --model flux_2_klein_4b_q6p.ckpt --image characters/<name>/photo.png \
  --width 704 --height 1280 --seed 11 --disable-preview --output characters/<name>/design_seed11.png \
  --prompt "Transform the toddler girl in the reference photo into a cute 3D Pixar-style animated cartoon character, keep her face shape, <hairstyle>, <outfit>, plain white sneakers with no logos, <carried item> with no tag. Full body, standing, facing the camera with a gentle smile, <background>, high detail 3D render, cinematic lighting."
```
- Use seeds 11, 22 and 33 for 3 images (about 52 s each), tile them into one image for the user to pick; **check shoes and toys for anything that looks like a brand mark**
- For emma the user picked seed 22 (two pigtails with pink hair ties, a pale-purple floral top, light-purple trousers, white shoes, hugging a yellow plush star)

## Step 2: write the script `scripts/<ep>.json`

Follow the format of `scripts/kid01.json`:
- `character_image`: the chosen design image; `character`: a text description of the character (**added verbatim to every shot** so it stays the same person)
- `look`: visual style; `motion_style`: prefix for the motion prompt
- `shots[]`: `dur` (seconds), `first` (first-frame description), `last` (last-frame description), `motion` (the action in between), `palette` (optional colour-reference image)
  - **One small action per shot**; the first and last frames are the start and end of that action (e.g. about to jump → already landed in the leaf pile)
  - Big actions turn to mush (emma's shot 4, "laughing and swaying", blurred the first time): write `only small subtle movement`
  - **The first and last frame must be the same scene**: use **the exact same scene sentence** in both descriptions (e.g. both say `in the same sunny green meadow with golden ginkgo leaves on the grass`). In emma's shot 7 the first frame was on the grass and the last on a path; the model forced the scene change and even the hair deformed
  - Don't let props "infect" the character: when blowing a dandelion, the model drew dandelion fluff into the pigtails. Write `her black pigtails and hair stay exactly the same` in `motion`; **after drawing the keyframes, look at the first and last frame with Read to confirm same scene, same hair**
  - Duration 1.0–1.6 s: 33 frames (≤ 1.4 s) or 41 frames. **Time cuts to the beat of the song**: get the start and end of every lyric line with whisper, and if you have a rhythm reference, detect cut points with `ffmpeg ... select='gt(scene,0.1)'`
- `subtitles[]`: `text`, `key` (keyword highlighted in yellow), `t0`, `t1`; one per lyric line
- `music`: `file` + `t0` (for the local preview); `cover_t`: which second to use for the cover; `output`

## Step 3: generate — **fixed order: make a 5-second preview first, and only do the rest once the user approves**

1. Make only the first 3–4 shots (about 5 s): `--only 1`, `--only 2`…, then compose a temporary 5-second preview (or temporarily keep only the first 4 shots in the JSON) and open it in QuickTime for the user
2. After approval, run everything; **report the actual time taken on delivery** (from the timestamps in log.txt) and how it compares with the previous episode

**Timing (measured on an M4 Pro, 24 GB)**: per shot ≈ FLUX drawing 2 keyframes (about 1.7 min) + 5B video (about 2–2.5 min) + a 15 s cool-down; CPU post-processing (grading, interpolation) runs in parallel in the background and adds no time → **about 4.2 minutes per shot, about 46 minutes for 11 shots**
- **GPU jobs can't run in parallel**: running FLUX and 5B together fights over the GPU; one video went from about 130 s to 291 s, so total time got worse, not better
- Faster options (ask the user first): set cool-down to 0 (hotter); fewer shots; generate at 480p and upscale (slightly softer)

### Commands (about 4 minutes per shot)

```bash
python tools/make_char_mv.py scripts/<ep>.json --only 1   # one shot first to check the look
python tools/make_char_mv.py scripts/<ep>.json            # everything (finished shots are skipped; resumable)
python tools/make_char_mv.py scripts/<ep>.json --compose  # re-compose only, after changing subtitles / music
```

For each shot, `tools/make_char_mv.py` does: FLUX draws the first + last frame (about 50 s each) → `mlx_wan22_i2v.py --image --last-image` (about 2 minutes) → grades twice (first back towards the first frame, then towards `palette`, removing the small model's plastic look) → trims the last 4 frames → fits the duration → de-flicker + interpolation to 60 fps; cool-down between shots.
Whole video: concatenate → subtitles (studio font `tools/fonts/Inter-Bold.ttf`, or the font set in `STUDIO_FONT`; white with a black outline and shadow, keywords in `#FFD93B` yellow, at 0.80 of the height) → music (loudness −16 LUFS, 0.5 s fade-out at the end) → cover.

**Pitfalls**
- Subtitle fonts: Inter is Latin-only, so Chinese subtitles need `STUDIO_FONT` pointing to a CJK font. With ffmpeg, `font='Hiragino Sans GB:style=W6'` matched a font without CJK glyphs (all tofu boxes), and drawtext can't pick a weight inside a .ttc — so extract the weight you need into a standalone .otf with fontTools
- Yellow keywords: measure the prefix width with PIL and overlay a second, yellow text layer; write the filter graph to a file and use `-filter_complex_script` (avoids shell escaping)
- FLUX doesn't always follow "holding it in her hand" (the star may float in the air); if it is acceptable, don't re-roll

## Step 4: check (always do this yourself)

At the end, `make_char_mv.py` runs automatic QC (resolution, 60 fps, audio track, duration, first frame not black, duplicate frames per shot) and writes `assets/<ep>/qc_sheet.jpg` (start, middle and end frame of every shot). **Open the sheet with Read and go through it shot by shot**:
- is it the same child in every shot (face, hair, clothes, carried item)?
- any deformation, extra limbs, mush, garbled text, brand marks?
- does the action match the description?

If a shot fails: delete `assets/<ep>/NN.mp4` (to redraw keyframes, also delete `keyframes/NN_a.png` and `NN_b.png`), adjust `motion` or `first`/`last`, and rerun (at most 2 re-rolls). There is no voice-over to check with whisper, but grab frames to confirm subtitle timing and the position of the yellow keywords.

## Step 5: delivery

- `open -a "QuickTime Player" works/<code>_<name>/<ep>.mp4`; cover at `works/<code>_<name>/<ep>_cover.jpg`
- Write `works/<code>_<name>/<ep>_post.txt` (same format as `video-skit`): title, description + engagement question + hashtags (e.g. #heartwarming #autumn #3Danimation #toddlerlife #AIanimation), **music: search for <song title> in the music picker, use the library version, start aligned to 0 s**, **tick "Content is AI-generated"**, collection name
- The video uploaded to the platform must be **the version without the song**: remove `music` and run `--compose` again (silent version), then add the music in the app

# video-idea

The front door for Douyin / Xiaohongshu videos. Use this first whenever the user describes any video idea, sends a screenshot of someone else's video asking "can you make this?" or "how would you do this?", or says "I have an idea". It checks the capability map to pick the right route (code 2D animation / Three.js 3D / Blender line art / 3D cartoon / realistic subtle motion / cloud), gives an honest quality estimate and time, writes a plan for the user to approve, then calls the matching skill or pipeline and puts the finished video in works/. Triggers - I have an idea, make a video, can you make a video like this, is this effect possible, make a video with Opus, help me build this, something like this video, Xiaohongshu video, /video-idea. If it is already clearly Aju, emma, Shuai & Mei, a quote video or an explainer, use that skill directly.

# Video idea → finished video (front door)

All commands run from the repo root.
**Step one is always reading `docs/capability-map.md`** (commands for every skill are in `docs/skills-index.md`): it has the route-selection table, the measured limits of each route and the known pitfalls. Folder rules are in `README.md`.

## Flow

1. **Understand the idea**: if it's a screenshot, work out what kind of video it is (code animation? 3D cartoon? realistic? a real person lip-syncing?); if it's a sentence, work out the core content and the emotion.
2. **Pick the route**: use section 2 of the capability map. If code (A) can do it, use code. Use AI imagery (B) only when you need characters and emotion, and in a realistic style only for subtle-motion shots. If it needs lip-sync or big facial expressions, tell the user it needs a cloud model (C).
3. **Be honest about expectations**: tell the user in one sentence what fraction of the reference you can match, where it falls short and how long it will take — don't oversell. When the user asks "how do other people manage it?", break down their method (Opus writes the script; which tool produces the pictures).
4. **Write the plan**: `works/<code>_<name>/PLAN.md` with the copy (narration line by line), shot list, style, duration and compliance notes. **Only start generating after the user approves.**
5. **Preview first**: for code routes, keyframe stills; for AI routes, 5 seconds or the first few shots. Make the full video only after the user approves.
6. **Full video → QC → delivery**: `works/<code>_<name>/` contains `<code>.mp4`, `<code>_cover.jpg`, `<code>_post.txt` (one version each for Douyin and Xiaohongshu). A new route also gets a `REPRODUCE.md`. Finally update the works list in `README.md`.

## Codes

`ep` quotes, Aju, fables; `kid` children's cartoon MVs; `zy` Shuai & Mei thinking series; `kp` code-animated explainers (2D, 3D, Blender); `xs` realistic subtle-motion series (new). A new video takes the next unused number: check with `ls works scripts` first.

## How to execute each route

| Route | How |
|---|---|
| A · 2D code animation | Use the `video-explainer` skill. Copy `scripts/kp01.json` and `tools/code_anim/kp01_compound.html` |
| A · Three.js 3D | Also `video-explainer`: load Three.js in the HTML (a pinned version from a CDN, or downloaded into `tools/code_anim/vendor/`), set the camera and objects from t inside `draw(t)` and call render; create the renderer with `preserveDrawingBuffer: true`. Starter: `tools/code_anim/three_template.html`. Rendered with the same `render.py` |
| A · floor-plan animation | Use the `video-floorplan` skill. Copy kp03 |
| A · Blender line art | Use the `video-lineart` skill. Copy `tools/blender_line/kp02_scene.py` and render with `make.py` |
| B · 3D cartoon | `video-char-mv` (photo-based character MV), `video-talk` (two-person dialogue) |
| B · realistic subtle motion | (1) make one look-defining reference image per character first (`characters/<name>/`); (2) each shot has only 1–2 characters with a blurred background; generate 4–6 candidates and have Claude reject ones with extra heads, extra hands or garbled text; (3) use chosen images as both first and last frame (or make the last frame a small edit of the first), `tools/mlx_wan22_i2v.py` at ≤ 73 frames per clip; (4) `tools/color_match.py` pulls the grade back to the first frame; (5) unified grade plus grain, 16:9 picture centred in the vertical frame, a low, calm narration + piano + small white subtitles |
| C · cloud | Tell the user it needs an API key for a cloud video model (e.g. Jimeng / Seedance or Kling) and the rough cost (about ¥1 per second). Once there's a key, write `tools/cloud_i2v.py` (not included yet) |

## House rules

- Plan first, then preview, then the full video; report the actual time taken on delivery
- For local GPU jobs, run a short test first, cool down between shots, and ask the user before long jobs
- Tick the AI label when publishing; no "AI" text on the picture; no third-party IP, no real people, no uniforms or law-enforcement imagery
- Found a new limit or a new pitfall? Update `docs/capability-map.md`

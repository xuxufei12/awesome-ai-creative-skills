````text
## Philosophy — What Makes 3b1b Different

3Blue1Brown videos are not *demonstrations* of math. They are **visual arguments** — the animation **is** the proof.

One invisible rule governs every Grant Sanderson video:
> *If you removed all the words, a patient viewer could still reconstruct the idea from the motion alone.*

| Standard animation | 3b1b-style |
|---|---|
| Shows a system, sweeps parameters | Builds intuition from first principles |
| One scene, one concept | Multiple chained scenes forming a narrative arc |
| Dashboard of numbers | Narration that thinks out loud |
| Static geometry that updates values | Objects that *become* other objects via `Transform` |
| Viewer watches a demo | Viewer reconstructs the idea themselves |
| Color as decoration | Color as a **concept identity** — one colour = one idea, forever |

This philosophy applies identically to pure math (eigenvalues), physics (wave propagation), engineering (pushover analysis), and geotechnics (slope stability). The medium is the same; only the plot recipes differ.

**Color vocabulary:**
- [Concept A] → [COLOR]
- [Concept B] → [COLOR]
- [Concept C] → [COLOR]
- (max 5 semantic colors; + one scaffolding grey)

**Domain preset:** [structural | geotechnical | seismic | probability | physics | ML | pure math]

Then **stop and wait** for the user's response. Do not begin coding.

**Act count is paper-driven — Claude decides.** Before writing the plan, Claude analyses the paper or topic and asks: *How many distinct ideas, derivations, or phenomena need their own visual argument?* The answer determines the act count. Never sacrifice a key idea to fit an arbitrary number.

**When to use `ask_user_input_v0` instead of prose:** If the user is ambiguous about domain or preset, prefer the tappable-button tool for those specific questions. For the full act plan itself, use the markdown table above — it conveys more structure than buttons.

# PART I — Rules That Prevent Crashes

These rules were learned from repeated production rendering failures. They are **NON-NEGOTIABLE**. Violating any one of them will either crash Manim, produce visibly broken output, or teach the viewer something false.

---

## RULE 1 — NEVER use `VGroup` for scene teardown ⛔

**The bug:**
```python
self.play(FadeOut(VGroup(*self.mobjects)))
# TypeError: Only values of type VMobject can be added as submobjects of VGroup
```
`self.mobjects` includes the Camera, which is a `Mobject` but not a `VMobject`.

**The fix — use this helper at the top of every script:**
```python
def clear_scene(scene):
    """Safe teardown — iterates mobjects and fades each one independently,
    so the Camera object (a Mobject but not a VMobject) never enters a VGroup."""
    mobs = [m for m in scene.mobjects]
    if mobs:
        scene.play(*[FadeOut(m) for m in mobs], run_time=0.5)
```

Call `clear_scene(self)` at the end of every Act. **Never** use `VGroup(*self.mobjects)`. If you must group leftovers to move them together, use `Group(...)` (accepts any `Mobject`), not `VGroup`.

---

## RULE 2 — NEVER put math, subscripts, or symbols inside `Text()` ⛔

**The bug:** `Text("IDR_max per story")` renders the literal string `IDR_max per story` on screen — the underscore appears as a visible character.

**The rule — three text classes, three uses:**

| Class | Use for | Never use for |
|---|---|---|
| `Text("...")` | Plain English sentences, titles, narration | Any math, subscript, superscript, Greek letter, `$`, `\` |
| `MathTex(r"...")` | **All** mathematical expressions | Plain English paragraphs |
| `Tex(r"...")` | Mixed prose + math (rare) | Use sparingly; prefer separate `Text` + `MathTex` |

```python
# ✅ CORRECT
label  = MathTex(r"IDR_{\max}", font_size=24, color=COL_DMG)
title  = Text("Interstory Drift Ratio", font_size=24, color=COL_DMG)
mixed  = Tex(r"Yield curvature $\varphi_y$", font_size=24)

# ❌ WRONG — underscore renders literally
label = Text("IDR_max", font_size=24, color=COL_DMG)

# ❌ WRONG — LaTeX in Text() does not render
label = Text(r"$IDR_{\max}$", font_size=24)
```

**Always use raw strings `r"..."` for `MathTex` and `Tex`.** Otherwise `\t`, `\n`, `\f` inside LaTeX get interpreted as Python escapes and break LaTeX compilation.

**Unicode in `MathTex`:** Greek letters, arrows, etc. must use LaTeX macros (`\alpha`, `\to`), never pasted Unicode (`α`, `→`). Unicode inside `MathTex` crashes LaTeX.

## RULE 3 — Three-zone layout per scene ⛔

Every scene is divided into three non-overlapping vertical zones:

```
┌─────────────────────────────────────────────────────┐
│  TOP ZONE    y ∈ [2.5, 4.0]                         │
│  Narration only. FadeOut BEFORE the main visual     │
│  is constructed or positioned.                       │
├─────────────────────────────────────────────────────┤
│  MID ZONE    y ∈ [-1.5, 2.0]                        │
│  Main visual (axes, diagrams, equations).            │
│  Centred, or split LEFT/RIGHT for side-by-side.      │
├─────────────────────────────────────────────────────┤
│  BOTTOM ZONE  y ∈ [-4.0, -1.8]                      │
│  Secondary annotations, result banners, credits.     │
└─────────────────────────────────────────────────────┘
```

**Enforcement rules:**
- Narration is `FadeOut` **before** the MID object is constructed — not merely before it is animated. (See Rule 3a below.)
- Within a single Act, when moving from sub-topic to sub-topic, explicitly `FadeOut` old elements before adding new ones.
- Annotations sit in the zone *opposite* the main visual. If the visual is LEFT, annotations go RIGHT; if CENTRE, annotations go BOTTOM.
- Never place two independent `Axes` objects or two diagram groups in the same zone simultaneously.

### RULE 3a — The most common violation (subtle)

**Wrong pattern — narr is on screen while the axis object is being CONSTRUCTED:**
```python
# ❌ WRONG
narr = Text("The rotation integral...", font_size=30)
narr.to_edge(UP, buff=0.6)
self.play(FadeIn(narr))
self.wait(1.2)

axes = Axes(...)           # ← CREATED while narr still on screen
axes.move_to(DOWN * 0.3)   # ← POSITIONED while narr still on screen

self.play(FadeOut(narr))   # ← faded too late — layout math already ran
self.play(Create(axes))
```

**Correct pattern — clear the zone FIRST:**
```python
# ✅ CORRECT
narr = Text("The rotation integral...", font_size=30)
narr.to_edge(UP, buff=0.6)
self.play(FadeIn(narr))
self.wait(1.2)
self.play(FadeOut(narr))   # ← cleared FIRST
self.wait(0.2)             # ← brief pause confirms zone is empty

axes = Axes(...)           # ← ONLY NOW construct MID objects
axes.move_to(DOWN * 0.3)
self.play(Create(axes))
```

**Strict rule:** `FadeOut(narration)` → `self.wait(0.2)` → **then** any MID-zone `move_to`/`next_to`/`align_to`/`Create`.

## RULE 4 — Explicit section management within each Act

Every Act is internally a sequence of named sections, each ending with a `FadeOut` of its own elements:

```python
class Act3_Example(Scene):
    def construct(self):
        self.camera.background_color = BG

        # ── SECTION A: Narration ──────────────────────────
        narr = Text("The opening question.", font_size=32, color=WHITE)
        narr.to_edge(UP, buff=0.6)
        self.play(FadeIn(narr, shift=UP * 0.15))
        self.wait(1.2)
        self.play(FadeOut(narr))          # ← fade before building visual
        self.wait(0.2)

        # ── SECTION B: Main visual ────────────────────────
        # ... build axes, diagram, etc.
        section_b_group = VGroup(axes, curve, labels)
        self.wait(0.8)

        # ── SECTION C: Annotation (only after B is stable) ─
        # If C would overlap B, clear B partially first.
        self.wait(1.5)

        # ── SECTION D: Result / revelation ────────────────
        self.play(FadeOut(section_b_group))   # clear B before D
        result = MathTex(r"...", color=COL_CAP)
        result.to_edge(DOWN, buff=0.5)
        self.play(Write(result), Flash(result.get_center()))
        self.wait(1.8)

        clear_scene(self)
        self.wait(0.4)
```

## RULE 5 — `tips=False` on most Axes; use arrowed axes only when semantically meaningful

```python
axes = Axes(
    x_range=[0, 1, 0.25], y_range=[0, 1, 0.25],
    x_length=5.0, y_length=3.5,
    axis_config={"color": COL_GRID, "stroke_width": 1.5},
    tips=False,    # ← default for data plots, pushover curves, CDFs
)
```

Arrowheads on axes are a graphical convention for *mathematical* coordinate systems (vector spaces, free-body diagrams, force diagrams). For **data plots** (stress–strain, pushover, fragility, hazard, time-history), tips look cluttered and should be off.

**Use `tips=True` when:**
- Drawing a vector basis in 2D or 3D (`NumberPlane` axes as a vector space)
- Free-body diagrams where axes represent force directions
- Mohr's circle (σ, τ plane used as vector space)

## RULE 6 — `VGroup` vs `Group` summary

| Use case | Correct class |
|---|---|
| Grouping `VMobject` elements (shapes, text, arrows, curves) | `VGroup` |
| Grouping mixed `Mobject` + `VMobject` (e.g., raster images + shapes) | `Group` |
| Scene teardown / fading all `self.mobjects` | Use the `clear_scene()` helper — **never** any group constructor |
| 3D objects (`Surface`, `ThreeDAxes`) with VMobjects | `Group` |

## RULE 7 — `stroke_dasharray` is NOT a valid Manim parameter ⛔

**The bug:**
```python
line = axes.plot(lambda x: 1.0, stroke_dasharray=[6, 4])
# TypeError: Mobject.__init__() got an unexpected keyword argument 'stroke_dasharray'
```
`stroke_dasharray` is SVG/CSS; Manim CE never implemented it.

**The fix:**
```python
# Dashed straight line
dashed = DashedLine(

)

# Dashed arbitrary curve
solid  = axes.plot(lambda x: np.sin(x), x_range=[0, PI])
dashed = DashedVMobject(solid, num_dashes=30)
```

color = interpolate_color("#CE93D8", "#81C784", 0.5)

## RULE 9 — `axes.get_area()` ONLY accepts `axes.plot()` outputs ⛔

**The bug:** Passing a manually built `VMobject` (via `set_points_as_corners`) to `axes.get_area(bounded_graph=...)`:
```python
# AttributeError: VMobject object has no attribute 't_min'
```
`get_area` internally calls methods that only exist on `ParametricFunction` objects.

**The fix — pick one of two options:**

**Option A (preferred):** both bounds are `axes.plot()` objects:
```python
upper = axes.plot(lambda x: mean(x) + 2*sig(x), x_range=[a, b],
                  color=COL_UNC, stroke_width=0.5)
lower = axes.plot(lambda x: mean(x) - 2*sig(x), x_range=[a, b],
                  color=COL_UNC, stroke_width=0.5)
band  = axes.get_area(upper, x_range=[a, b], bounded_graph=lower,
                      color=COL_UNC, opacity=0.25)
```

**Option B:** pre-computed point arrays → wrap in `Polygon`:
```python
upper_pts = [axes.c2p(x, mean(x) + 2*sig(x)) for x in xs]
lower_pts = [axes.c2p(x, mean(x) - 2*sig(x)) for x in xs]
stride = 8  # Polygon slows down with >50 vertices
band = Polygon(
    *upper_pts[::stride], *lower_pts[::stride][::-1],
    fill_color=COL_UNC, fill_opacity=0.25, stroke_width=0
)
```

## RULE 10 — `always_redraw` is a module-level function, NOT a method ⛔

**The bug:**
```python
label = MathTex(r"P", font_size=24)
label.always_redraw(lambda: label.next_to(arrow, LEFT))
# AttributeError: MathTex object has no attribute 'always_redraw'
```

**The fix:**
```python
# Module-level function returns a fresh live-updating object:
label = always_redraw(lambda: MathTex(r"P", font_size=24).next_to(arrow, LEFT))
```

**Important trade-off:** `always_redraw` rebuilds the object every frame. For simple translations (e.g., a load label that moves with its arrow), it is far cheaper to put the label inside a `VGroup` with the arrow and animate the group:
```python
load_grp = VGroup(load_arrow, P_lbl)
self.play(load_grp.animate.shift(RIGHT*2))   # cheap, smooth
```
Use `always_redraw` only when the label's value, size, or content genuinely changes every frame (e.g., a `DecimalNumber` tied to a `ValueTracker`).

## RULE 12 — Prefer separate `MathTex` objects over character indexing ⛔

**The fragile pattern:**
```python
eq = MathTex(r"Q = \tau D^\top D + \mathcal{I}")
SurroundingRectangle(eq[0][11:19], ...)   # character positions vary with whitespace, braces, LaTeX expansion
```
LaTeX compilation decides character counts per run. What worked in testing breaks on a minor edit.

**The robust fix — build separate `MathTex` objects per colour/highlight:**
```python
# ✅ CORRECT
eq_full = MathTex(r"Q_{\mathrm{post}} = \tau D^\top D + \mathcal{I}", font_size=44)
eq_full.move_to(UP * 1.3)
self.play(Write(eq_full))

lbl_prior = VGroup(
    MathTex(r"\tau D^\top D", font_size=28, color=COL_PRIOR),
    Text("smoothness prior", font_size=19, color=COL_PRIOR)
).arrange(DOWN, buff=0.12).next_to(eq_full, DOWN, buff=0.5).shift(LEFT*2.2)
```

**Exception — `MathTex` with split substrings + `TransformMatchingTex`:** If you build `MathTex` with **explicit substrings**, matching transforms are reliable:
```python
# Reliable: give MathTex each substring separately
lhs = MathTex(r"M", "=", r"\varphi", r"EI", font_size=44)
rhs = MathTex(r"\sigma", r"\cdot", r"I", font_size=44)
self.play(TransformMatchingTex(lhs, rhs))
```
The rule is: don't slice character indices of a monolithic string; do split the string into meaningful pieces at construction time.

## RULE 13 — LaTeX package requirements (engineering notation) ⛔

**The problem:** Out-of-the-box, Manim's LaTeX preamble supports `amsmath`, `amssymb`, `dsfont`. It does **not** include `siunitx` (needed for `\SI{10}{\kilo\newton}`, `\qty{}`, `\unit{}`) or `physics` (for `\dv{}{}`, `\pdv{}{}`).

**The bug:**
```python
MathTex(r"F = \SI{138.8}{\kilo\newton}")
# LaTeX error: Undefined control sequence \SI
```

**The fix — extend the TexTemplate at module level:**
```python
from manim import TexTemplate

ENG_TEMPLATE = TexTemplate()
ENG_TEMPLATE.add_to_preamble(r"""
\usepackage{siunitx}
\usepackage{physics}
""")

# Then pass tex_template= to each MathTex that needs it:
F = MathTex(r"F = \SI{138.8}{\kilo\newton}", tex_template=ENG_TEMPLATE, font_size=36)

# Or set globally (applies to ALL MathTex in the file):
MathTex.set_default(tex_template=ENG_TEMPLATE)
```

**If the user has no `siunitx` installed**, fall back to manual notation: `MathTex(r"F = 138.8\ \mathrm{kN}")`. This always works and looks professional.

## RULE 14 — Manim's cache can outlive your edits ⛔

**The surprise:** You edit your script, re-render, and the video shows the *old* version. Manim caches rendered partial-movie files under `media/videos/<script>/<quality>/partial_movie_files/` and its Tex compiler under `media/Tex/`.

**Fixes (from least to most aggressive):**
```bash
python -m manim -qh --flush_cache script.py Act1_Hook   # clears partial movies only
rm -rf media/videos/<script>/<quality>/partial_movie_files
rm -rf media/                                           # nuclear — also re-compiles LaTeX
```

Routine advice: **when in doubt, delete `media/` and re-render.** The cost is render time; the benefit is certainty.

## RULE 15 — Use `axes.c2p()` for positioning; NEVER raw data units as coordinates ⛔

**The bug:**
```python
dot = Dot([0.5, 100, 0], color=RED)   # interpreted as 0.5 units, 100 units → off-screen
```

**The fix:**
```python
dot = Dot(axes.c2p(0.5, 100), color=RED)   # data coords → scene coords
```

`c2p` (coords-to-point) maps data units into the Axes's local scene units. The inverse, `p2c`, maps scene point → data. Every dot, arrow, label that lives "on" an Axes must use `c2p` or `next_to(axes.c2p(...), DIR)`.

## RULE 16 — Log scales: Manim does not support them natively ⛔

Hazard curves, S–N diagrams, and many geotechnical plots need log axes. `Axes` has no `log=True` parameter.

**The fix — use a linear axis of `log10(value)` and add custom labels:**
```python
# Data: return periods 50, 100, 500, 1000 years; IMs 0.1–2.0 g
log_imin, log_imax = np.log10(0.05), np.log10(2.5)
axes = Axes(
    x_range=[log_imin, log_imax, 0.5],
    y_range=[-5, -1, 1],            # log10 of annual frequency of exceedance
    x_length=6, y_length=4,
    tips=False,
    axis_config={"color": COL_GRID, "stroke_width": 1.2},
)

# Custom x-tick labels at 0.1, 0.3, 1.0, 2.0 g
for v in [0.1, 0.3, 1.0, 2.0]:
    tick = MathTex(f"{v:g}", font_size=18).next_to(axes.c2p(np.log10(v), -5), DOWN)
    self.add(tick)

# Custom y-tick labels: 10^{-5}, 10^{-4}, ...
for p in range(-5, 0):
    tick = MathTex(fr"10^{{{p}}}", font_size=18).next_to(axes.c2p(log_imin, p), LEFT)
    self.add(tick)

# Plot λ(IM) = k0 * IM^{-k} → in log–log: log λ = log k0 - k log IM (a line)
k0, k = 1e-3, 2.3
curve = axes.plot(lambda lx: np.log10(k0) - k * lx, x_range=[log_imin, log_imax],
                  color=COL_MODEL, stroke_width=3)
```

## RULE 17 — Stroke widths: defaults are too thick for 3b1b aesthetic

Manim's defaults (`stroke_width=4` for `Line`, `3` for `ParametricFunction`) look chunky and amateurish.

**Recommended hierarchy:**
```python
# Axis gridlines, reference lines    → 1.0–1.5
# Secondary curves, auxiliary geometry → 2.0–2.5
# PRIMARY concept curves              → 3.0–3.5
# Absolute focal element (ONE per scene) → 4.5–5.0
```
Set once at file top via `Mobject.set_default`, or pass per-call.

## RULE 18 — Manim version compatibility ⛔

This skill targets **Manim Community Edition ≥ 0.18.0**. Earlier versions (ManimGL, Manim 0.17 and below) have different APIs. Check once before coding:

```bash
python -m manim --version   # expect: Manim Community v0.18.x or higher
```

If the user is on an older version, offer to either (a) upgrade (`pip install -U manim`), or (b) adapt the code for their version. Do **not** silently produce code that won't run.

Key differences to watch for on very old versions:
- `Tex.set_opacity(...)` was `Tex.fade_to(...)` on pre-0.14
- `NumberPlane` default colours changed in 0.17
- `ValueTracker` has always been there, but `self.play(tracker.animate.set_value(x))` pattern is 0.15+

## RULE 19 — `MovingCameraScene` teardown and camera reset ⛔

When using `MovingCameraScene` (zoom/pan), the `clear_scene` helper still works, but **reset the camera frame to its original state** before the next Act or the final `Write` will be off-screen:

```python
class ActZoom(MovingCameraScene):
    def construct(self):
        self.camera.background_color = BG
        self.initial_frame_state = self.camera.frame.save_state()   # save at start
        # ... zoom around ...
        self.play(Restore(self.camera.frame))   # reset at end
        clear_scene(self)
```

## RULE 20 — `ThreeDScene` has its own teardown trap ⛔

`ThreeDScene.mobjects_without_canvas` excludes the axis frame (which is part of the "canvas"). The safe pattern:

```python
class Act3D(ThreeDScene):
    def construct(self):
        self.set_camera_orientation(phi=65*DEGREES, theta=-55*DEGREES)
        # ... add axes, surfaces ...
        # Teardown — remove, do not fade, to avoid artefacts with 3D fill:
        self.play(*[FadeOut(m) for m in self.mobjects_without_canvas], run_time=0.5)
        # Then reset orientation if the next Act is 2D:

## 2.3 Motion grammar — verb reference

Every animation verb has a semantic meaning. Reusing verbs consistently across Acts helps viewers parse the video.

```python
# Appearance
Write(eq)                              # equations, handwritten feel
FadeIn(mob, shift=UP*0.2)              # text entrance — slight shift adds life
FadeOut(mob)                           # exit — use explicitly, constantly
Create(shape)                          # border drawing
DrawBorderThenFill(shape)              # filled shapes

# Transformation — semantic hierarchy
Transform(A, B)                        # A morphs into B; the variable A now IS B
ReplacementTransform(A, B)             # A is removed; B takes its place (safer)
TransformMatchingTex(eq1, eq2)         # morph matching LaTeX substrings
TransformMatchingShapes(A, B)          # morph by geometric shape similarity

# Emphasis
Indicate(mob, color=YELLOW)            # brief pulse-highlight
Circumscribe(mob)                      # circle or rectangle border
Flash(point, color=WHITE, num_lines=12) # revelation moment (use sparingly — ~3 per video)
Wiggle(mob, scale_value=1.1)           # attention, unstable feeling

# Choreography
LaggedStart(*anims, lag_ratio=0.1)     # staggered entrance
AnimationGroup(*anims, lag_ratio=0)    # parallel, no stagger
Succession(*anims)                     # strict sequential

# Dynamics
ValueTracker(init_val)                 # animatable scalar
always_redraw(lambda: ...)             # rebuild every frame
TracedPath(dot.get_center)             # trail behind a moving dot
```

**Rule for `Transform` vs `ReplacementTransform`:** if you will reference the original object later, use `ReplacementTransform` (the new object keeps a clean identity). If the object is one-off and the code then keeps using the original variable name, `Transform` is fine. When in doubt, `ReplacementTransform`.

## 2.4 Pacing rules

- Minimum `self.wait(0.5)` between any two animations.
- Minimum `self.wait(1.2)` after any narration text appears.
- Minimum `self.wait(1.5)` after any `Flash` or revelation moment.
- Maximum 3 simultaneous `Animation` objects in a single `self.play()`. More than three tends to produce visual confusion. Split.
- Maximum ~7 s between any "breath" — a beat of `self.wait(1)` with no new animation. The viewer needs micro-pauses.

## 2.5 Composition rules

- **Golden-ratio framing for primary subjects:** main subject at x ≈ ±1.5, not at x = 0, for better visual balance.
- **Symmetry for comparisons:** when comparing two things, mirror-symmetric placement about the y-axis (`LEFT*3` vs `RIGHT*3`).
- **Alignment:** use `.align_to(other, direction)` rather than hard-coded coordinates whenever objects share a baseline.
- **Buffer consistency:** use the same `buff` value (e.g., `0.35`) for related groups.

# PART III — Act Library

Choose **6 or more Acts** per video — six is the floor, not the target. Claude reads the paper or topic first, lists every distinct idea that needs a visual argument, then assigns one Act per idea. Every Act has a specific pedagogical job. Every Act ends with `clear_scene(self)`.

## 3.1 Universal Acts (any domain)

### `Hook`
**Job:** make the viewer feel the problem viscerally, before any formalism.
- Open with a question in plain English (≤ 10 words)
- Show one concrete, surprising visual — no equations yet
- End with the question left open: *"There must be a better way."*
- **Duration:** 25–40 s

### `Build_Intuition`
**Job:** establish the prerequisite picture from first principles.
- Start from something familiar (a line, a circle, a simple frame)
- Incrementally transform via `ReplacementTransform` into the full concept
- Label every new element as it appears, in its concept colour
- End with the complete picture, labeled, clean
- **Duration:** 35–60 s

### `Animate_Equation`
**Job:** make a single equation *speak* — every symbol becomes a geometric object.
- Display equation with `Write()`
- `Indicate` each term; reveal the geometric object it represents
- Use `ValueTracker` + `always_redraw` to couple a symbol's value to its geometry live
- **Duration:** 30–50 s

### `Reveal_Structure`
**Job:** show that two apparently different things are secretly the same.
- Present structure A (fully labeled)
- Present structure B next to it
- `ReplacementTransform` morphs A into B — viewer sees equivalence
- `Flash` at the moment of equivalence
- **Duration:** 30–50 s

### `Probabilistic_Argument`
**Job:** show why one deterministic answer is not enough.
- Show the spread of outcomes (histogram, CDF, ensemble of curves)
- Animate the distribution as a parameter varies
- Mark the observed value against the distribution
- **Duration:** 30–45 s

### `Compare_Methods`
**Job:** two methods side by side — make the difference visceral.
- Left panel: Method A, build, result
- Right panel: Method B, build, result
- Bottom: direct numerical or visual comparison
- `Flash` + `Indicate` on the winning result
- **Duration:** 35–50 s

### `Implications`
**Job:** show what the result *enables* that was not possible before.
- Pipeline diagram: boxes + arrows
- 3–4 consequences, each fading in as its own line in its concept colour
- **Duration:** 25–40 s

### `Callback`
**Job:** return to the opening question and answer it definitively.
- Echo the Hook's visual (same diagram, same question)
- Now answer it with the formula or result built earlier
- Final `Flash` + revelation sentence
- Credits in `GRAY_C` at bottom
- **Duration:** 25–40 s

# PART V — Mathematical & Physical Correctness

A category of error that has nothing to do with Manim syntax, but produces videos that are **wrong**.

## 5.1 Never approximate a plotted quantity by intuition — compute it

When a paper plots a derived quantity (Fisher information, posterior variance, pushover curve from a real model, RMSE curve), it is tempting to write a "plausible-looking" lambda that produces a roughly correct shape. This produces a video that *looks* right but teaches the viewer something false — the worst possible outcome for an educational video.

### Example (real production bug)

The Fisher informativeness curve for a boundary sensor at x/L = 0 was approximated as:
```python
# ❌ WRONG APPROXIMATION — gives ~0 for the support sensor
def info_curve(x, sensor_pos):
    if x < sensor_pos:
        base = 4.0 * x**2 * (1 - sensor_pos)**2
    else:
        base = 4.0 * sensor_pos**2 * (1 - x)**2
    return base * 90
# Result: info_curve(any_x, sensor_pos=0.0) ≈ 0 everywhere.
# This is physically WRONG. A support sensor DOES carry information.
```

**The correct approach — numerical precomputation at module level:**
```python
# ✅ CORRECT — compute the actual integral from the paper's formula
def _compute_fisher(r_sensor, N_elem=55, K_loads=80):
    """
    I^(i)_jj = (1/sigma^2) * sum_k A^2_(i,k),j
    where A_(i,k),j = integral over element j of m_r(s) * M(s;z) ds
    m_r(s) = (1-s) if s > r, else (-s)        [unit couple at r]
    M(s;z)  = (1-z)*s if s<=z, else z*(1-s)   [unit load at z]
    """
    xs = np.linspace(1./(2*N_elem), 1. - 1./(2*N_elem), N_elem)
    dx = 1. / N_elem
    zs = np.linspace(0.02, 0.98, K_loads)
    FI = np.zeros(N_elem)
    for j, xj in enumerate(xs):
        s_lo = max(xj - dx/2, 1e-5)
        s_hi = min(xj + dx/2, 1. - 1e-5)
        ss = np.linspace(s_lo, s_hi, 20)
        tot = 0.0
        for z in zs:
            m_r = np.where(ss > r_sensor, 1. - ss, -ss)
            M_z = np.where(ss <= z, (1.-z)*ss, z*(1.-ss))
            tot += np.trapezoid(m_r * M_z, ss) ** 2
        FI[j] = tot
    return xs, FI

# Precompute ONCE at import time, outside any Scene class
_fi_xs, _fi_vals = _compute_fisher(r_sensor=0.25)
fi_fn = lambda x: float(np.interp(x, _fi_xs, _fi_vals))

# Inside the Scene:
curve = axes.plot(fi_fn, x_range=[0.01, 0.99], color=COL_FISH, stroke_width=3.5)
```

**Key pattern:** expensive computations (integrals, matrix operations, iterative solvers, Newmark-β for time histories, Mohr–Coulomb root-finding for slope stability) belong at **module level**, run once at import. Scene classes stay fast and purely visual.

### Verify before rendering

```

## 5.2 Units — write them; check them; show them

Engineering videos without units are useless. Physics videos without units are confusing.

**Inside `MathTex`, use one of:**
```python

```

**Sign conventions — always state them once, in the Build_Intuition Act:**
- Compression positive (geotech) or compression negative (structural mechanics)?
- Moment positive if it causes tension in the bottom fibre?
- Angle measured from horizontal or vertical?

**Unit-check heuristics (verify dimensions at module level):**
```python
# Base shear: force = mass * acceleration
# If V = 138.8 kN and W = 2000 kN (weight), then V/W = 0.0694 (dimensionless)
# Sa_y = V/W should be < 1.0 for typical RC buildings: ✅
assert 0.01 < Vb/W < 0.5, f"Sa_y out of physical range: {Vb/W:.3f}"

# Period: T = 2π√(m/k) seconds

T_eff = 2*PI*np.sqrt(dy*1e-3 / (9.81 * Vb/W))
assert 0.3 < T_eff < 2.0, f"Effective period seems off: T = {T_eff:.2f} s"
```

## 5.3 Sign conventions & coordinate axes

State the convention **on-screen** in the first Act where it matters. Examples:

- **Mohr's circle:** τ downward for counterclockwise rotation (geotech convention), or τ upward (structural convention). Choose one and stick with it.
- **Pushover:** positive Δ in the direction of applied load. Show the direction with an arrow in the Hook.
- **Slope stability:** safety factor F > 1 is stable. State this explicitly.
- **Seismic spectrum:** Sa at the SDOF's undamped natural period. Say "for 5% damping" explicitly.

## 5.4 Don't invent data — either use real paper values, or say "illustrative"

If the plan is for a real paper, extract the paper's real numbers (tables, figures) and hard-code them into the script. Cite the paper in the Credits card.

If the numbers are illustrative (made up for pedagogy), put a small `Text("illustrative values", font_size=16, color=GRAY_C)` in the corner of the scene. Never present invented numbers as if they were real.

## 7.2 Concatenation (`concat.py`) — always provide this

Always ship `concat.py` alongside the main script. It avoids the Windows BOM encoding bug that breaks `filelist.txt` when created in Notepad or via shell redirection, AND validates that all files exist before concatenating.

```python
# concat.py — Run after rendering all acts
# Usage: python concat.py
import os, sys, subprocess

SCRIPT_NAME = "your_script_name"   # filename without .py
QUALITY     = "1080p60"            # matches -qh
OUTPUT      = "output_final.mp4"

ACTS = [
    "Act1_Hook",
    "Act2_Name",
    "Act3_Name",
    "Act4_Name",
    "Act5_Name",
    "Act6_Name",
]

media_dir = os.path.join("media", "videos", SCRIPT_NAME, QUALITY)
filelist  = "filelist.txt"

# Validate all files exist before building the list
missing = []
paths = []
for act in ACTS:
    p = os.path.abspath(os.path.join(media_dir, f"{act}.mp4"))
    if not os.path.isfile(p):
        missing.append(p)
    paths.append(p)

if missing:
    print("❌ The following rendered files are missing:")
    for m in missing:
        print("   ", m)
    print("\nRender them first with:  python -m manim -qh <script>.py <ActName>")
    sys.exit(1)

with open(filelist, "w", encoding="utf-8") as f:    # utf-8 without BOM
    for p in paths:
        f.write(f"file '{p}'\n")

cmd = ["ffmpeg", "-y", "-f", "concat", "-safe", "0",
       "-i", filelist, "-c", "copy", OUTPUT]
print("Running:", " ".join(cmd))
r = subprocess.run(cmd)
if r.returncode == 0:
    print(f"✅ Done! Output: {OUTPUT}")
else:
    print(f"❌ ffmpeg failed with exit code {r.returncode}")
    sys.exit(r.returncode)
```

# Part IX — Quality checklist & anti-patterns master table

## 9.1 Pre-render checklist

Before running the first `manim` command, walk this list top-to-bottom:

### Structural integrity
- [ ] Every Act is its own `Scene` subclass (separate file or clearly delimited class).
- [ ] Every Scene ends with `self.wait(0.5)` and explicit teardown via `clear_scene()`.
- [ ] No `VGroup` is used to teardown objects containing updaters or `always_redraw`.
- [ ] Every section inside a Scene is wrapped in its own `with self.section():` block (or manually timed with `self.wait`).

### Text & mathematics
- [ ] Mixed-language Tex uses raw strings: `Tex(r"\LaTeX here")`.
- [ ] No `MathTex` contains prose; no `Text` contains LaTeX math.
- [ ] Colored terms are built as separate `MathTex` pieces or use `TransformMatchingTex` with a well-defined `.get_part_by_tex()` map.
- [ ] All engineering units render via `siunitx` (`\SI{138.8}{\kilo\newton}`) or a `\mathrm{}` fallback.
- [ ] Sign conventions appear on-screen whenever stress / strain / displacement are plotted.

### Layout
- [ ] Narration text lives in the top ~25 % of the canvas.
- [ ] Visual (plot, diagram) lives in the middle 50 %.
- [ ] Annotations and captions live in the bottom ~25 %.
- [ ] No overlap between MID-zone construction and TOP-zone narration still on screen.
- [ ] All positioning uses `axes.c2p()` when data coordinates are involved — never raw floats that look like data units.

### Numerical honesty
- [ ] Every plotted quantity is *computed*, never drawn to look right.
- [ ] Expensive computations live at module level, not inside `construct()`.
- [ ] `print()` statements verify key numbers (Vb, Δy, φ_y, μ_φ, λ_collapse, FS) before the rendering run.
- [ ] Dimensions are asserted for every array that feeds a plot.
- [ ] `np.trapz` replaced by `np.trapezoid` if on NumPy ≥ 2.0.

### Visual hierarchy
- [ ] Grid lines at `stroke_width ≤ 1.5`.
- [ ] Reference / secondary curves at `stroke_width 2.0–2.5`.
- [ ] Primary curves at `stroke_width 3.0–3.5`.
- [ ] The single focal element at `stroke_width 4.5–5.0` (used sparingly, ≤ 1 per scene).
- [ ] `tips=False` on data axes unless the axis represents a vector basis or FBD force arrow.
- [ ] ≤ 4 distinct semantic colors live on screen at any moment.

### Rendering hygiene
- [ ] Render first pass at `-ql` (low quality) to catch logic errors fast.
- [ ] Final pass at `-qh` (1080p60) only when the whole sequence plays clean.
- [ ] `--flush_cache` was used after any significant refactor.
- [ ] `media/` directory was purged if a stale cached frame appears mid-animation.

### Concatenation
- [ ] `concat.py` checks `os.path.exists` for every input clip before writing `list.txt`.
- [ ] Clips are in the intended order (Act 1 → Act N).
- [ ] Final `final.mp4` renders start-to-end cleanly.


## 9.2 Anti-patterns master table

This single table consolidates every footgun identified in Parts I–VIII. Whenever Claude writes Manim code, it scans this list before compiling.

| # | Anti-pattern | Why it breaks / looks amateurish | Correct move |
|---|---|---|---|
| **Teardown** |
| A1 | `self.play(FadeOut(VGroup(*self.mobjects)))` | Includes camera, grid, frame → crashes on `ThreeDScene` / `MovingCameraScene` | `clear_scene()` helper that iterates and filters |
| A2 | `*[m for m in self.mobjects]` inside `VGroup(...)` | Same as A1; VGroup rejects non-VMobject children | Use `Group(...)` or filter with `isinstance(m, VMobject)` |
| A3 | Not clearing updaters before FadeOut | Updater keeps firing on a removed mobject → error | `mob.clear_updaters()` then fade out |
| A4 | Leaving `always_redraw` objects at scene end | Redraw callback persists into next scene's namespace | Convert to static `mob.copy()` before teardown |
| **Text / LaTeX** |
| B1 | `MathTex("The sum is equal to")` | Italic math-mode renders prose weirdly; spacing wrong | `Tex(r"The sum is equal to")` or `Text("The sum is equal to")` |
| B2 | `Text(r"\alpha = 0.5")` | Plain Text doesn't parse LaTeX; draws literal backslash | `MathTex(r"\alpha = 0.5")` |
| B3 | `MathTex("\\alpha")` (un-raw string) | Escape confusion; sometimes silently wrong | `MathTex(r"\alpha")` — always raw for LaTeX |
| B4 | Trying to color a single letter inside `MathTex("V_b = 138.8 \\text{ kN}").set_color_by_tex("V")` | `set_color_by_tex` matches entire tex tokens, not letters | Split: `MathTex(r"V_b", r"= 138.8~\text{kN}")` and color [0] |
| B5 | Forgetting `\usepackage{siunitx}` in TexTemplate | `\SI{…}{…}` fails to compile | Custom TexTemplate with siunitx / physics preloaded |
| **Layout** |
| C1 | Placing new content while narration still on screen | Cognitive overload; violates three-zone rule | `FadeOut(narration_top)` first, then build middle |
| C2 | Using `.move_to([3, 1, 0])` on plotted points | Raw units look like data coords → confuses positioning | `axes.c2p(3, 1)` always |
| C3 | Overlapping labels on a plot | Unreadable at 1080p | `next_to(point, direction, buff=0.15)` with consistent buffer |
| C4 | Centering wide formulas at `ORIGIN` | Overflows safe area | Scale to `width=config.frame_width*0.9` then `.move_to(ORIGIN)` |
| C5 | Building 3 plots side-by-side without a coordinating VGroup | Misalignment, drift | `VGroup(p1, p2, p3).arrange(RIGHT, buff=0.8)` |
| **Axes** |
| D1 | `Axes(tips=True)` on data plots | Looks like cartoon math; arrows imply continuation beyond data | `tips=False` on data; `tips=True` only for vector bases / FBDs |
| D2 | Linear axes for hazard curves or S-N diagrams | Crushes all the data into the corner | Manual log axis: plot `log10(x)` on a linear axis with custom labels |
| D3 | Default axis number formatting | Shows `1000.0` where you want `1.0e3` or `1 kN` | `x_axis_config={"decimal_number_config": {"num_decimal_places": 1, "unit": r"\text{m}"}}` |
| D4 | Using `axes.get_area(…, x_range=…)` on a curve not built by `axes.plot(...)` | Returns garbage / errors | `get_area` only accepts `ParametricFunction` returned by `axes.plot` |
| **Animations** |
| E1 | `self.play(*many_anims)` with 10+ animations | Viewer can't track > 3 changes simultaneously | `LaggedStart(..., lag_ratio=0.1)` |
| E2 | No `wait` between animations | Feels rushed, unreadable | Min 0.5 s between; 1.2 s after narration; 1.5 s after a `Flash` |
| E3 | `Transform(A, B)` when A and B have different structures | Morphs into visual mush | `ReplacementTransform(A, B)` or `FadeOut(A); FadeIn(B)` |
| E4 | `Indicate(mob, color=RED)` on a RED object | No visible change | Indicate to a contrasting color |
| **Colors** |
| F1 | More than 4 semantic colors on screen at once | Viewer loses which color means what | Keep to ≤ 4 active semantic colors; recycle via fade |
| F2 | `interpolate_color(RED, BLUE, 0.5)` without `ManimColor` | Returns tuple in some versions, errors in others | `interpolate_color(ManimColor(RED), ManimColor(BLUE), 0.5)` |
| F3 | Using `YELLOW` and `GOLD` as distinct semantic channels | Colorblind viewers can't distinguish | Use shape / stroke pattern as secondary channel |
| **Numerics** |
| G1 | Plotting "approximately the right curve" | Dishonest; pedagogically wrong | Compute the actual quantity, even if slower |
| G2 | Computing inside `construct()` | Re-runs on every render invocation | Module-level precompute; `construct` only animates |
| G3 | Reading data files with relative paths | Breaks when Manim is invoked from a different cwd | `os.path.dirname(__file__)` or absolute paths |
| G4 | No sanity prints before rendering | You only notice wrong numbers after watching the video | `print(f"Vb = {Vb:.1f} kN")` at module level |
| **Lines & dashing** |
| H1 | `Line(…, stroke_dasharray=[0.1, 0.1])` | Parameter doesn't exist in Manim CE | `DashedLine(…, dashed_ratio=0.5)` or `DashedVMobject(line)` |
| H2 | Arrow with default buff | Tip overshoots the target mobject | `Arrow(…, buff=0.1)` explicit |
| **3D** |
| I1 | `self.play(FadeOut(*self.mobjects))` in `ThreeDScene` | Includes the camera → crash | Use `self.mobjects_without_canvas` |
| I2 | `self.set_camera_orientation(phi=60*DEGREES, theta=-45*DEGREES)` without reset | Next scene inherits the rotation | Reset to `phi=75, theta=-30` at Act end |
| I3 | 3D arrows on data plots | Terrible depth cues; always look wrong | Prefer 2D projections with shading |
| **Camera (MovingCameraScene)** |
| J1 | Zoom in and never reset | Next scene starts mid-zoom | `self.camera.frame.save_state()` at Act start, `restore()` at end |
| J2 | Rotate camera frame then `Transform` objects | Transform applies in screen coords, looks wrong | Reset frame rotation before Transforms |

| **Rendering** |
| L1 | Only rendering at `-qh` during development | Slow iteration; debugging cost is high | `-ql` until everything works, then `-qh` once |
| L2 | Leaving `media/` cache across refactors | Old frames reappear in new scenes | `--flush_cache` or delete `media/` directory |
| L3 | Parallel render of Scenes that write to same filename | File collision; corrupted output | Unique output name per Scene; use Manim's default naming |
| **NumPy / dependency** |
| M1 | `np.trapz(...)` on NumPy 2.0+ | `AttributeError: module 'numpy' has no attribute 'trapz'` | `np.trapezoid(...)` (available in 1.x too via alias) |
| M2 | `from manim import *` mixing with `from manimlib import *` | Two different packages; ambiguous class names | Pick Manim Community (`from manim import *`) exclusively |
| M3 | Using `always_redraw` as a method (`axes.always_redraw`) | It's a module-level function in CE | `from manim import always_redraw`; wrap as `always_redraw(lambda: ...)` |
| **Engineering-specific** |
| N1 | M-φ curve with straight-line yield-to-ultimate branch | Hides the strain-hardening physics | Compute from fibre section; let curvature grow and recomputed M |
| N2 | Pushover with no post-peak softening | Misrepresents real RC frame behavior | Use verified fibre-section values; show softening post-μ = 1 |
| N3 | Mohr's circle drawn but principal stresses not marked | Viewer doesn't see the take-away | `Dot` + label at (σ₁, 0) and (σ₃, 0) with rotation arc |
| N4 | Slope stability without factor-of-safety equation | Visual only; no quantitative bridge | Overlay `FS = (c·L + ΣW cos α tan φ) / ΣW sin α` with highlights |
| N5 | Consolidation isochrones without T_v labels | Looks like random curves | Label each curve with T_v = 0.01, 0.1, 0.5, 0.9 |
| N6 | Response spectrum without damping ratio labels | Can't tell curves apart | Annotate ζ = 2 %, 5 %, 10 %, 20 % at right end |
| N7 | Fragility curve on linear PGA axis | Lognormal shape gets squashed at low IM | Linear is acceptable here; log only for hazard curves |

## 9.3 Final quality bar

Before Claude considers a plan / render complete, it asks:

1. **Would Grant Sanderson publish this?** If any colored term or transition feels arbitrary, redo it.
2. **Does every second earn its place?** Cut any Act whose pedagogical delta is redundant.
3. **Can a non-expert follow the argument?** If the viewer needs the paper open, narration is too dense.
4. **Is every number on screen traceable?** If pressed, Claude should be able to reproduce every numeric label from code.
5. **Does the final callback close the loop?** Every 3b1b-style video ends by returning to the opening question with a new perspective.

# Part X — Troubleshooting tree

When a render fails or looks wrong, traverse this tree top-down. Each node ends in a concrete fix.

## 10.1 Render fails with an exception

### LaTeX error: `! Undefined control sequence`
→ Missing package in TexTemplate. Add to preamble:
```python
tex_template = TexTemplate()
tex_template.add_to_preamble(r"\usepackage{siunitx}")
tex_template.add_to_preamble(r"\usepackage{physics}")
tex_template.add_to_preamble(r"\usepackage{amsmath,amssymb}")
MathTex.set_default(tex_template=tex_template)
```

### LaTeX error: `! Missing $ inserted` with Tex
→ You mixed math and text without `$...$`. Use `Tex(r"The result is $\alpha = 0.5$")` not `Tex(r"The result is \alpha = 0.5")`.

### `AttributeError: module 'numpy' has no attribute 'trapz'`
→ NumPy ≥ 2.0. Replace with `np.trapezoid`.

### `AttributeError: 'Axes' object has no attribute 'always_redraw'`
→ `always_redraw` is module-level: `from manim import always_redraw`.

### `TypeError: VGroup accepts only VMobject`
→ You tried to VGroup a `Group`, `Image`, or `ThreeDVMobject`. Swap `VGroup` → `Group`.

### `RuntimeError: Cannot call updater after mobject removed`
→ An `always_redraw` or `add_updater` fires on an already-faded mobject. Before fade: `mob.clear_updaters()`.

### `FileNotFoundError` during `concat.py`
→ Validate existence:
```python
missing = [c for c in clips if not os.path.exists(c)]
if missing: raise FileNotFoundError(f"Clips missing: {missing}")
```

### LaTeX compile hangs forever
→ Infinite loop in TeX (usually a bad `\newcommand`). Kill the process, inspect the TexTemplate preamble, remove the culprit.

### `PermissionError: [Errno 13] ... media/`
→ `media/` directory is locked (Windows, often). Close any open video previews and retry.

## 10.2 Render succeeds but output looks wrong

### Text is tiny / huge
→ Font size is absolute. Use `font_size=36` for narration, `48` for titles, `28` for annotations. Or `.scale_to_fit_width(config.frame_width * 0.8)`.

### Colors look washed out
→ Check background: `config.background_color = "#1C1C2E"` (not pure black; pure black kills color contrast on compressed video).

### Plot axes extend off-screen
→ Axes auto-size from the x_range / y_range. Wrap: `axes.scale_to_fit_width(11)` then `axes.move_to(ORIGIN)`.

### Numbers are wrong on screen
→ You didn't compute them; you hard-coded guesses. Revisit the module-level precompute block, add `print()`, rerun.

### Animation feels rushed
→ Your `self.wait(...)` calls are < 0.5 s. Standard pacing: 0.5 s between animations, 1.2 s after narration text, 1.5 s after a `Flash`.

### Animation feels slow
→ Use `LaggedStart(*anims, lag_ratio=0.1)` to stagger 10 items in ~1 s total. `run_time` parameter on `play()` overrides default 1 s.

### Transform morphs into visual mush
→ Source and target have different object counts. Use `ReplacementTransform` (just swap) or `FadeOut(A); FadeIn(B)`.

### Colored LaTeX term doesn't colorize
→ `set_color_by_tex` matched more than one token. Split into separate `MathTex` pieces and color them individually.

### Camera is stuck zoomed-in or rotated in the next scene
→ Previous `MovingCameraScene` didn't `restore()` the saved state, or `ThreeDScene` didn't reset `set_camera_orientation`. Add explicit reset at end of every camera-moving scene.

### 3D plot has inverted z-axis or weird depth
→ `ThreeDScene.set_camera_orientation(phi=75*DEGREES, theta=-30*DEGREES)` is the house default. For top-down: `phi=0, theta=-90*DEGREES`.

## 10.3 Output is correct but the video doesn't teach

### Opening doesn't hook
→ Act 1 should be a concrete puzzle, a visual question, or a paradox. Never open with "In this video we will cover…".

### Middle drags
→ Check whether every Act adds *one* new idea. If two Acts teach the same point with different examples, cut the weaker one.

### Ending falls flat
→ The final Act should *call back* to the opening hook. Viewer should feel the loop closing: "now I see why that puzzle had that answer".

### Viewer can't follow the math
→ Every colored term must be introduced *before* the equation it lives in. Build intuition on the axis before you land the formula.

### The video explains *what* but not *why*
→ Add an Act called "What if this weren't true?" — visually violate the assumption and show what breaks. This is the 3b1b signature move.

## 10.4 Escalation

If none of the above fixes the problem, escalate:
1. Re-read the original paper/spec. Often the issue is a conceptual mismatch, not a code bug.
2. Render a single Act in isolation to isolate the failure.
3. Strip the Scene down to the minimum that reproduces the issue.
4. Consult the Manim Community Discord / GitHub issues for the exact error message.

- Probability: prior `#A89A85`, likelihood `#6DA7E4`, posterior `#6FAF62`

**Stroke width hierarchy**
- Grid 1.0–1.5
- Secondary 2.0–2.5
- Primary 3.0–3.5
- Focal (max 1) 4.5–5.0

**Pacing defaults**
- Between animations: 0.5 s
- After narration text: 1.2 s
- After `Flash` / `Indicate`: 1.5 s
- `LaggedStart` lag_ratio: 0.1 for groups ≤ 10 items, 0.05 for larger

**Render flags**
- Dev: `-ql` (480p15)
- Final: `-qh` (1080p60)
- Flush: `--flush_cache`
- Single scene: `-qh file.py SceneName`

**Teardown**
```python
def clear_scene(scene):
    for m in list(scene.mobjects):
        m.clear_updaters()
    scene.play(*[FadeOut(m) for m in scene.mobjects if isinstance(m, VMobject)])
    scene.mobjects.clear()
```

**Concat (with validation)**
```python
import os, subprocess
clips = [f"media/videos/act{i}/1080p60/Act{i}.mp4" for i in range(1, 7)]

    for c in clips: f.write(f"file '{c}'\n")

                "-c", "copy", "final.mp4"], check=True)
```
````

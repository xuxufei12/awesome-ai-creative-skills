# DeepBlend Studio

You drive a Blender workbench. The scene is not a `.blend` file you edit — it is a
**SceneSpec** document, and every accepted change compiles that document into a new,
immutable **revision**. Everything you do is one of: read a revision, propose a patch
that becomes a revision, render a revision, or judge what a render measured.

## The cost asymmetry decides everything

Two kinds of render exist and they differ by three orders of magnitude:

| | `blender_preview_render` / `blender_preview_views` | `blender_final_render` |
|---|---|---|
| What it is for | looking at the scene | producing the deliverable |
| Resolution / engine | 640×360, fast engine, few samples | whatever the `final` profile says (typically 1920×1080, Cycles, hundreds of samples) |
| Measured cost | seconds for the whole image | **19.6–41.4 s for ONE frame** on the machine this was built on |
| A typical job | — | 450 frames ≈ **3.4 hours** |

So: **look with previews, and never start a final render to find out what something
looks like.** A final render is the last step of a decision you have already made,
not a way to make one. If you catch yourself wanting "just one frame to check", that
is a preview.

A final render is also the one operation that may need approval (SPEC §15.1), and it
is the one that can outlive the process. Treat starting it as a commitment — and know
the way out: **`blender_job_cancel`** stops it and *measures* that the renderer is gone
rather than assuming the signal landed. Cancelling keeps every frame already written, so
a cancelled render is resumable with `blender_final_render {resumeJobId}`, and a partially
written frame is re-rendered rather than kept. Cancel a render you no longer want; never
start a second one beside it, because a project can only have one delivery render at a
time (`RENDER_JOB_CONFLICT`).

## The order that works

### Complete a declared recipe task with few operations

When a recipe covers the requested object and its declared parameter ranges,
use those controls directly. For a brief asking for an editable Blender file
and a preview, create with `saveCheckpoint: true` and `renderPreview: true` in
the same `blender_project_create` call. Keep the recipe identity and digest,
requested values, saved revision, checkpoint and preview receipts together.
Do not create the default object and then rebuild dimensions already covered
by its controls. Read the returned receipts before asking for the full scene.

Creation, dimensional saves and patches with preview enabled can include the
verified saved preview image in the same result. Inspect that image first; do
not render the same view again just to retrieve it. For a visible patch, request
checkpoint and preview together. When a result says its image was not attached,
the model has not seen those pixels; retain the saved artifact and report that
limit. Additional views still need to show the features required by the brief.

For an existing assembly dimension edit, the final handoff must be a compact receipt:
- project/current revision and the retained original;
- requested dimensions as saved controls, and the measured native spans with their coordinate basis;
- saved custom keyframe timing and protected cameras when requested;
- the actual registered native file and primary/back images;
- the remaining score findings and unmeasured global conditions.
Do not add component tables, inferred margins, or a prose retelling of movement groups.
A distance from the object origin to one sampled face is one-sided evidence, not a
measured overall size. Do not double it into a measured width/depth/height without
checking the opposite boundary. Give any interval its exact coordinate basis and
whether it covers a half-span or full span; do not call a doubled full interval a
half-depth. Saved controls and world-axis extents are sufficient when intrinsic
overall geometry has not been measured; do not invent extra measurements.
Do not infer no floating, no interpenetration, topology or clearance from beauty previews.
Without corresponding measurements those conditions remain unassessed, even if a view looks good.
The save receipt and scene document contain the detailed part changes for inspection.
The save receipt's generatorChangedEntityIds explicitly lists structurally resized parts.
When it is nonempty, never say "no part size changed" or "all part geometry unchanged".
Preservation applies to the original revision and independent hand edits, not to the
structural generator dimensions requested to change.
Structural shells, openings, baffles and panels grow: the recipe's fixed-part wording is
not a claim that those structural dimensions stay unchanged. If the user explicitly asks
for a detailed component report, quote actual receipt fields individually and retain gaps.

For a later dimensional change, read `blender_recipe_parameters`, then save
only the changed parameter IDs with the current base revision and preview
enabled. This preserves independent appearance, the original revision and
the declared attachment/framing links. If a controlled field conflicts, resolve
that actual conflict instead of silently replacing a hand-edited model.

For a saved glazed cup, the dimensional entry preserves its placed object pose.
A recognized default camera rig moved/turned with that cup can follow dimensions;
independent lens/target edits, deleted cameras and authored camera animation stay
protected. Render the saved result and check that the whole cup and joins fit.
A protected camera is not a promise of an uncropped view; report it or use an
explicitly requested photography edit. Preserve the user's lights and floor.

A cup's body diameter excludes its handle. `cup-outer-diameter-mm` controls
twice the body radius; the whole object's bounding box includes the handle.
Declared wall thickness and sampled technical checks do not certify a global
minimum wall or manufacturing tolerance.

For a dimension or assembly check, read a few relevant saved parts with
`blender_scene_get {projectId, revision, geometryEntityIds, geometryFrame}`.
Use IDs from the returned scene and the explicit frame of the preview being checked.
This measures the actual saved native mesh without a render or another revision;
prefer that small receipt to repeated full-scene searches when you need bounds or
transforms. Keep its source revision and checkpoint hash with the result. World-axis
spans include rotation, handles and protrusions: they do not prove body diameter,
wall thickness, clearance or quality. If a part is unavailable or the runtime refuses
inspection, state that limit instead of substituting generator settings as measurements.
After changing dimensions, check the affected parts and important attachments again,
then use actual preview pixels to judge the finish and joins.

Do not turn the difference between shell and liner outer bounds into an assembly
gap. It includes shell material and depends on curvature and orientation; it is
not the distance from the shell's inner surface to the liner. An unchanged height,
position or scale also cannot establish preserved wall thickness or clearance.
When those conditions are requested, distinguish the recipe's linked design rule
from actual surface measurements. Without a separate supported surface check,
report wall thickness and clearance as unmeasured; do not give a numeric gap or
claim "basically preserved" from bounding dimensions or preview pixels.

For actual local surface evidence, the same tool optionally accepts
`geometrySurfaceSamples` (1–8). Each sample supplies `sampleId`, a selected
`entityId`, an outside `originMeters`, a non-zero `direction`, and explicit
`searchDistanceMm` (0.01–500); optional `targetEntityId` must be another selected
part. Choose seeds from actual saved bounds and the requested region, not from
declared thickness or gap values. The runtime follows the first entry face's
normal to its first exit and, if requested, the target's first entry. Keep seeds,
frame, part IDs and source SHA with the receipt; use the same explicit seeds to
compare saved revisions. A failed sample is unavailable, never zero.

Use `geometryOnly:true` with the native selection for a compact measurement receipt;
it keeps the complete verified objects, samples and source identity while omitting
the scene catalogue. Read the scene separately when selecting parts or seeds.
It cannot be combined with `full:true`.

For a dimension edit, request `geometryObjectAxes:true` together with the selected
native IDs and explicit frame. In a v3 receipt, `objectAxisExtentMm` directly measures
full evaluated mesh extents along the object's own physical orthogonal axes, including
native construction/world scale. `objectAxisWorldMatrix` states those normalized axes
and the native origin; `objectAxisBasis` is `evaluated-object-axes-scaled`. Use this
returned evidence instead of inverting a world bounding box or doubling one-sided rays.
For the pinned cabinet-shell these axes correspond to shell width/depth/height. They
are full per-object mesh extents; for a handled cup, for example, protrusions are included
and they do not by themselves establish body diameter or wall thickness.
`objectAxisStatus:unsupported-object-axis-basis` has no axis numbers: a sheared or
degenerate basis must stay unavailable while world measurements can remain available.
Do not apply native scale a second time. A non-unit native scale can come from a
primitive's construction, even when the authored SceneSpec scale is [1,1,1]; it does not
establish a manual scaling edit or a recipe-to-body mismatch.

For saved native size/movement comparisons, use `geometryCompareRevision` with the
old saved revision, the selected `geometryEntityIds`, and explicit `geometryFrame`.
Without surface samples, `geometryComparison.objects` gives current-minus-reference
world-axis span and object-origin changes. Use these computed values instead of
subtracting rounded displays. This does not identify their cause or certify contact.

For explicit attachment endpoint origins, add `geometryAssemblyPairs` (1–8 pairs),
each with a distinct `pairId`, selected `entityId` and different selected
`anchorEntityId`. `geometryAssemblyOrigins` joins native OBJECT ORIGINS in world XYZ:
entity minus anchor. With a reference revision, `geometryComparison.assemblyOriginComparison`
also returns the offset changes. These are not surface protrusion, seating depth,
contact or clearance. World offsets change with rotation; do not call them intrinsic
or anchor-local dimensions. Preserve unavailable endpoints without inventing zero.

For local surface before/after comparisons, supply `geometryCompareRevision` with the
old saved revision and the same explicit samples on the current read. The tool verifies both
sources and computes `geometryComparison.samples` changes (current minus reference)
and maxima over **all** comparable requested samples. Chord-only samples still count
in the chord maximum. Unavailable pairs are omitted from numeric changes, never zero.
Use these computed summaries rather than mental arithmetic. Preserve sample IDs,
coverage counts and unavailable rows; round only for display. Do not assert left/right
symmetry or an explanation for a change from this summary. A world seed does not
necessarily hit the same material point across revisions. If the comparison is
unavailable, report the raw evidence and limit the claim instead of guessing maxima.
The comparison also computes percent changes against each reference value. Quote
the separate chord and separation percentage maxima exactly (round only for display).
Do not apply a chord percentage to the gap, derive percentages from rounded table
values, or introduce a combined relative bound. If no percentage receipt exists,
omit the percentage claim. Do not equate a measured change with user approval of
its size; state the observed values and coverage, and leave unmeasured conditions open.

`normalSurfaceChordMm` runs from source entry to source exit. Target
`normalRaySeparationMm` runs from source **EXIT** to target entry along that
inward normal, excluding the source chord. Describe those two surfaces explicitly;
do not label it as source outer surface to target entry or as global free clearance.
Triangle-face normals differ from shading normals. These samples do not prove
global minimum wall thickness, whole-assembly free clearance, no collision,
manufacturing safety or visual quality. Other scene objects and mesh
self-intersections are not certified. Chord/target searches each stop at 100 mm;
unsupported topology, overlap, occlusion and missed rays must remain explicit.
If no supported samples cover a requested condition, keep it unmeasured.

Inspect the saved preview needed for the brief; add a targeted view if it does
not show the requested features. Once the requested native file and preview
are saved, conclude with the project, revision and actual delivery paths.
Use the current operation's returned project-relative paths and identify the project
and revision. A historical producer path does not establish the current store root.
Do not guess absolute paths from old metadata. If a generic presentation tool cannot
register a project-relative file, report its path and use the saved workbench preview;
do not invent a successful attachment or search unrelated stores to fabricate one.
Separate verified dimensions/topology from appearance observations. An
unavailable vision reviewer is a limitation to report, not a reason to repeat
unchanged renders or to claim artistic approval. Additional artistic review
and final rendering follow the user's delivery requirements.

### Establish the visual target before building

Record the intended object, dimensions, audience, material identities and delivery
views in the project goal. Bind available reference images as immutable project assets
through `project.referenceImages`; describing a file in the goal does not attach it.
For the import, binding and evidence rules, read [Reference image workflow](references/reference-images.md).
If no reference is
available, state the chosen proportions and finish as assumptions. Break a product
into named parts with distinct silhouettes, seams, thickness and material assignments.
Choose a route for each part: import an authorized asset, use a supported procedural
shape, or build a blockout pending a more capable modeling operation. A blockout is
an intermediate result; describe its missing details explicitly.

For rotational products, use `generator.shape: "lathe"` with an ordered
`profile: [[radius, height], ...]`; returning along the inside models a real wall
and base. Add profile points along curved shoulders instead of stacking cylinders.
For a cylindrical ceramic cup with a connected semicircular handle, use
`shape:"handled_cup"`. Defaults make a 40 mm radius, 105 mm high cup with 3 mm
walls and a 5 mm base in a metre scene. `handleLower`/`handleUpper` locate the
attachment centres; `handleRadius`, `rootRadius` and `rootLength` control the
handle and flared roots. Dimensions constrain one another; an unsupported edit
is refused before publication. The generated mesh is checked for topology, UVs
and illegal intersections. Inspect actual clay and glazed root close-ups;
these checks do not certify curvature continuity, manufacturing thickness or
artistic quality. Existing modifier stacks can change the generated result.

For handles and cables, use `shape: "curve"`, a three-dimensional `path`, `radius`,
and `pathInterpolation: "bezier"` for smooth bends. Check joins and self-intersections;
overlapping parts are not automatically fused into one solid.
Use ordered entity `modifiers` for solidify (wall thickness), mirror, array and
boolean union/difference/intersect. A boolean's `targetEntityId` names a separate
single-mesh operand; set that operand's `visible:false` to avoid rendering it twice.
Inspect the resulting junction: a watertight union does not automatically create
a rounded transition. Generator bevel runs before these modifiers. Add
`{type:"bevel",width:0.002,segments:6,angle:30}` after a boolean to round its new
edges (width is a local distance; angle is in degrees). Overlap clamping can reduce
the width on dense geometry, so inspect close-ups and adjust the join when needed.

The entity bevel modifier accepts `miterInner:"arc"|"sharp"`. Omission preserves
the existing arc behavior. Sharp can avoid crossing artifacts around curved bores;
it does not guarantee a smooth union or solve the vessel-handle seam. This option
does not belong to `generator.bevel`. Inspect real close-ups after changing it.

Use these checkpoints before delivery:

For environmental reflections and illumination, ingest an equirectangular
HDR/EXR (linear Rec.709) or PNG/JPEG (sRGB), declare it, and set
`world:{strength:0.6,environment:{assetId:"studio-environment",rotation:0}}`.
Rotation is around world Z in radians. `world.set` replaces the whole block;
retain the environment when adjusting strength, omit it to return to flat color.
Check highlight placement on the product, not only the background image.

For brushed metal, use a Principled material with `parameters.anisotropic` in
[0,1] and `anisotropicRotation` in turns (0.25 = 90 degrees). Set a real tangent
with `material.tangent.set`: `{mode:"uv",uvMap:"UVMap"}` follows that named UV
map, or `{mode:"radial",axis:"z"}` follows Blender's cylindrical projection
around the object's local x/y/z axis. Active anisotropy requires Cycles; emission
materials reject these fields. Nonzero strength/rotation or their animation
requires an explicit tangent. UV existence is checked on faces actually using
the material, after local slot overrides, including evaluated native curves and
text without changing their source data. Zero strength and rotation can
remove tangent with null. Inspect changed highlights in a close-up; procedural
noise can add microtexture but is not a substitute for anisotropic reflection.

For procedural grain, set the full texture with material.texture.set. Coordinates
default to object space. Use coordinates:"uv" and optional uvMap:"UVMap" to
follow an authored surface layout; omitting the UV name uses the active render
layer. Named maps must exist on every evaluated surface actually using the
material; unused slots do not block compilation. UV mode requires principled
or glass. On lathe UV (U around circumference, V along profile), noise with
scale:1 and stretch:[0.0001,800,1] follows circumferential lines. Compare roughness
and grain separately under fixed lighting and camera; UV frequency is layout
relative, not a physical groove measurement.

For image PBR, ingest PNG/JPEG maps and declare the returned assets, then use
`material.images.set` with baseColor/roughness/metallic/normal/alpha/emissionColor
bindings. Each binding names an assetId; optional scale and offset are UV vectors,
uvMap names an existing UV layer. Scalar maps support channel r/g/b/a (default r),
normal supports strength and expects OpenGL tangent-space data. Color maps are sRGB;
numeric maps are Non-Color. Clear procedural texture before binding images. Maps
replace their socket values; emissionColor still needs emissionStrength. Verify
actual texture scale and surface response in a close-up, not only node existence.

Revise existing geometry with `entity.generator.set` (replace the full generator)
and `entity.modifiers.set` (replace the full ordered stack; [] clears it). Preserve
entity identity so material, camera and animation references survive the edit.

1. **Proportions:** inspect a neutral clay preview from front, side and three-quarter
   views. Compare silhouette, scale and part placement with the goal/reference.
2. **Geometry:** inspect a close-up for edge rounding, wall thickness, joins and
   repeated details. Use the generator's bevel where suitable; increasing render
   samples cannot repair a coarse silhouette or missing geometry.
3. **Materials and lighting:** preserve imported materials unless an override is
   intentional. Inspect metal reflections, surface roughness, glass transparency,
   texture scale and contact shadows. Keep preview and final color transforms the
   same so a finish approved in preview survives final rendering.
4. **Motion:** inspect the first, middle and last frames and every important reveal.
   Check intersections, framing and whether the lighting still describes the shape.

For each checkpoint, record what was inspected, what remains wrong and the next
specific change. A high composition/exposure score does not establish visual quality.
When the current tools cannot produce an essential detail, report that limitation
and propose an asset or supported construction that meets the requirement.

To inspect geometry and finish independently, first call `blender_scene_get` for
the revision and existing cameras. Call `blender_preview_render` with explicit
`revision`, `cameraId`, `frame` and `mode:"clay"`; repeat with `mode:"beauty"` at
the same camera and frame. For example:

```json
{"projectId":"product","revision":"r0003","cameraId":"camera-detail","frame":1,"mode":"clay","samples":16}
```

These inspections require Host API 6 or newer and attach the verified PNG when
an attachment store is available. If the result says no image was attached, the
model has not seen it; read the actual image before making visual claims. Images
are rebuilt from SceneSpec in independent storage and do not alter the source
revision or ordinary previews. Clay removes transparency, emission, textures and
bump/normal response; imported shader displacement can change the rendered shape.
It does not prove wall thickness, manifold geometry, no intersections or artistic
approval. Use declared cameras for front, side, three-quarter and detail checks;
if a needed camera is absent, add it through the normal revision workflow first.
Record the source revision, camera, frame, mode and concrete findings, then patch
the current revision and repeat the affected views with the same settings.

1. **`blender_capabilities`** — what this Blender can actually do: engines, formats,
   GPU. Call it once per session before promising anything. It reports absence as
   data (`installed: false` plus a warning), never as a crash.
2. **`blender_recipe_list` / `blender_project_create`** — inspect locally validated product recipes
   before building a matching product from scratch. Create from the returned recipe id, version
   and digest, with only its declared parameter overrides; never combine recipe with sceneSpec.
   Recipe colors are scene-linear RGB, not hex/sRGB. Source/license/hash metadata does not prove
   authorship or artistic quality. A project owns its SceneSpec, revision history and render output;
   the first revision is `r0001`. If no recipe fits, use a supplied scene or the minimal scaffold route.
   For an existing assembly, use **`blender_recipe_parameters`** with `action:read` first.
   Use the returned revision, numeric parameter IDs and allowed ranges in `action:save`.
   Read/save receipts include linkedAnimationTracks from the selected saved SceneSpec. Use its
   actual keyframe frames and values to verify custom timing and travel; recipe defaults, shot
   prose and the observation/render frame are not the current animation keyframe list.
   This creates one revision in the same project, using ordinary patches internally; it preserves
   independent materials, bevels, photography and history. Do not recreate the project to resize it.
   Save receipts include placementChanges: groups of actual saved object-origin deltas in mm,
   with entity IDs and from/to revision. Quote the group containing each named part; front
   controls and rear connectors may move in opposite directions. These SceneSpec deltas
   are not native surface distances or clearances.
   A part following an assembly edge can change its offset from the cabinet centre. Do not
   describe all relative offsets as invariant. A world-coordinate endpoint is not an exposure
   or clearance distance. If no returned field defines a relationship measurement, leave it
   unmeasured instead of deriving an attachment distance or margin in the final answer.
   Pinned speaker 2.0/2.1 assemblies can retain a complete manual translation or XYZ rigid
   pose while resizing when every original part and the button rest anchors agree. A rotated
   button needs the corresponding saved world-axis curves; retain their actual timing/travel.
   For a tilted button, a world-Z change alone is not its total travel. Compare the measured
   XYZ endpoints at the authored rest/press frames: report those components separately, or
   use their Euclidean displacement magnitude for total travel; never label just Z as travel.
   Partial moves, independently rotated parts, scaling and missing animation anchors remain
   conflicts. Keep custom photography and verify framing; add a complete delivery view when
   a protected camera clips the enlarged assembly, without replacing that authored camera.
   For whole-product delivery, select the cabinet shell explicitly with preview_views.subjectId
   and track the shell and named end parts; automatic subject selection may choose a cable.
   Inspect each full-resolution saved front/back PNG, not only the small contact sheet.
   frameBoundaryContacts reports image-edge contact for tracked silhouettes even when they
   are not the selected subject. A positive silhouette with inFrame:false or a bbox touching
   0/1 cannot support a claim of complete framing. Pixel masks end at the image edge; a
   high score, VALID scene or some projected corners inside is not proof of a complete view.
   Keep authored cameras unchanged. If the requested full product touches an edge, add a
   separate delivery camera with breathing room, render it and inspect the new saved image.
   Contact-free selected parts still do not certify untracked geometry or occlusion.

   Native world-axis spans change with rotation and cannot certify cabinet-local width/depth/
   height. Distinguish saved size controls from those measured spans. Do not undo the user's
   placement or scale the assembly to make world spans match the requested local dimensions.
   If a multi-part speaker review reports the shell hidden behind its own fitted
   front/rear enclosure panels, inspect the named entities and saved recipe first.
   For the pinned speaker, front-baffle and rear-service-panel are authored enclosure
   parts. Preserve their existing tags and add subject-part through ordinary
   entity.tags.set when those declarations are missing, then rerun the same review.
   Retain the original review and all remaining findings. Do not tag the floor,
   unrelated objects or every scene entity as subject-part to raise a score, and
   do not delete, hide or move parts or protected cameras to make a review pass.
   Keep the current measured findings even for the environment or a detail camera.
   Their tags or intended purpose alone do not establish that a finding is a non-defect.
   A verified enclosure-part declaration does not clear floor occlusion or framing issues.
   Prefer the parameter/native tool receipts over filesystem searches for dimensions,
   animation or registered files; do not reverse-engineer dimensions from world bounds.
   Controlled geometry conflicts require resolving the named parts before saving. Old recipes
   without geometry controls return available:false. Use a fresh idempotencyKey for each new
   intent, including edits after restoring history; reuse it only for the same retry.
3. **`blender_asset_ingest`** — import an authorized model or image into project storage.
   Declare its returned asset descriptor in a patch, then bind its intended use:
   a model instance, material map, environment, or review reference. See the model
   workflow below and the reference image guide above.
   `blender_project_get.projectDirectory` is the active project directory, including after
   relocation or restore. Combine it with returned project-relative artifact paths for file
   registration. Do not guess a producer's old absolute directory from historical metadata.
4. **`blender_scene_get`** — read before writing. Patching without reading is how a
   stale `baseRevision` produces a refusal you then have to diagnose.
   For exact fields of one saved entity in a large scene, use `sourceEntityId`.
   This selects an entity, not an animation-track, camera or asset-descriptor ID.
   Read camera/track fields from the scene catalogue or `full:true`, without
   `sourceEntityId`; do not combine the two read modes.
   It returns bounded compact JSON `sourceText`, `nextOffset`, revision and
   `entityJsonSha256`. Continue with that explicit revision and `sourceOffset:nextOffset`,
   verify the hash stays identical, concatenate the chunks in order, then parse JSON.
   `nextOffset:null` ends the entity. `sourceLimit` is 1–2048 characters; escaped
   text may return fewer. Do not combine this mode with full or geometry reads.
   This preset has no generic `read` tool: do not spend repeated grep calls trying
   to reconstruct multiline control vertices from spilled full-scene output.
   Imported models commonly have an empty container with nested mesh children. For the
   complete instance, request `geometryEntityIds:[assetId,supportId]`,
   `geometryAssetInstanceIds:[assetId]`, `geometryFrame` and `geometryOnly:true`.
   Do not combine aggregate instance bounds with `geometryObjectAxes` or
   `geometrySurfaceSamples`. A multi-part hierarchy has no single physical part axis.
   ASSET_MESH_SET reports actual evaluated world bounds and mesh counts. The ID is the
   scene entity ID, not the source asset descriptor ID. Missing/hidden/unsupported or
   over-budget children make the entire instance unavailable: never substitute its
   origin, a declared dimension, a partial child or zero for the measured bottom.
   For a deliberately horizontal flat pedestal, compare the measured instance min Z
   to support max Z, preserve the old revision, change only the intended instance
   transform through a patch, remeasure and inspect the base in an actual close view.
   Bounds separation is not a surface contact or collision certificate.

   For framing, select the required complete subjects and `geometryCameraId` at an
   explicit `geometryFrame`; use `geometryAssetInstanceIds` for imported subjects.
   `geometryCameraMargin` defaults to 0.03. Read cameraProjection.normalizedBounds,
   containedInFrame and containedInClip, rather than guessing from object origins.
   Intended detail crops are different from an establishing shot that loses its finial.
   Test shot endpoints, interior extrema and transition-adjacent frames; verify every
   rendered frame before final delivery. Projection does not detect an intervening
   column, tree, wall, camera collision, or later motion. Inspect actual pixels too.
   Never automatically replace an old project's manually authored cameras or geometry.
5. **`blender_scene_patch`** — submit ordinary scene edits as bounded operations. There is no free-form
   edit and no script. See "Revision discipline" below.
   For complex custom geometry, prefer 1–6 coherent operations per call. Reuse exact
   saved entities with entityCopies to avoid resending long arrays. This is not a hard
   limit or permission to split dependent atomic edits. Send complete strict JSON;
   after refusal, inspect the error paths and dryRun validation before retrying.
   Harness MALFORMED_RESPONSE occurs before this tool and does not mean an edit was
   accepted. Never silently repair/execute truncated JSON or claim the tool fixed it.
   `blender_asset_ingest.license` is a string, but `asset.add.asset.license` is an object
   with source, commercialUse and attribution. Keep the returned asset descriptor.
   `cube.size` is one scalar; do not pass a vector as its size.
   To reuse exact saved geometry without repeating control arrays, supply up to16
   `entityCopies:[{sourceEntityId,newEntityId,transform?}]` from `baseRevision`.
   These become ordinary entity.add operations before `operations` (which may be []).
   Transform components are absolute overrides; omitted components and other authored
   entity fields remain exact. Each source must exist in that saved revision; target IDs
   must be new and distinct. References are retained, not remapped; child assemblies and
   animation tracks are not copied. Decide placement explicitly and inspect native
   contact and actual renders. Copying does not create a natural layout automatically.
   `entityCopyOffset:[dx,dy,dz]` translates all selected copies by one common world-metre
   displacement, preserving their relative placement. Omit every copy's transform.location
   in this mode; per-entity rotation/scale overrides remain absolute. Select every required
   part explicitly: unselected references/dependencies and animation are not moved/copied.
6. **`blender_preview_render` / `blender_preview_views`** — look at it. `preview_views`
   renders several declared views in one Blender launch and returns contact sheet
   paths and measurements, and attaches the verified saved contact sheet for image-capable models.
   Inspect those pixels directly; a separate reviewer call is for independent judgement, not image access.
   For a specific part, use `preview_render` with an explicit cameraId, frame and beauty/clay mode;
   do not rename camera roles or reorder cameras to obtain a targeted view. Single-frame `preview_render`
   attaches an independent inspection when an explicit beauty/clay mode is set.
7. **`blender_visual_review`** — ask for a measured judgement (see "Who decides what").
8. **`blender_visual_autofix`** — iterate against the revision's saved goal and
   reference images with a bounded budget. It requires evidenced artistic judgment
   as well as technical measurements; it cannot rewrite the target to obtain a pass.
9. **`blender_final_render`** — only once the preview is right. It returns as soon as
   the job is durable, not when it finishes.
   The default renders one camera. Saved `shots` metadata does not switch cameras.
   For an authored multi-shot film, explicitly set `useShotCameras:true`; every
   requested frame must belong to exactly one saved shot with its `cameraId` and
   `frameRange`. Do not also select `cameraId`. A missing capability/camera or an
   uncovered/overlapping range is a refusal, never permission to use one fallback
   camera for the whole film. The job freezes this selection and binds actual
   per-frame camera IDs to the output PNGs. A delivery needs consecutive frames;
   use named-camera previews for separated spot checks, never a final render to
   discover whether the composition is right.
10. **`blender_job_status`** — poll it, or come back to it in a later turn. A render
    that outlives the process is still there: the store is on disk.
11. **`blender_export`** — publish the delivery package when you want it verified and
    described rather than merely finished.

`blender_scene_validate` fits anywhere: it checks a scene, or a patch you have not
committed yet (`dryRun`), without touching the project. Use it when a patch is refused
and the reason is not obvious.

## Bringing in a model the user already has

`blender_asset_ingest` copies a file into the project; it **does not touch the scene**.
Two steps follow it, and a scene that skips the second one has an asset nobody uses:

1. `blender_asset_ingest {projectId, sourcePath}` — a local file, no approval. Pass
   `sourceUrl` instead and the call **pauses to ask the operator**, because it leaves
   the machine. Use `sourcePath` whenever the file is already there.
2. `blender_scene_patch {op: "asset.add", asset: {id, type, path, sha256}}` — declare it,
   using the `assetId`, project-relative `path` and `sha256` the ingest returned. This is
   what commits it: one accepted patch, one new revision, like every other change.
3. `blender_scene_patch {op: "entity.add", …}` with `type: "asset-instance"` and that
   `assetId` — now something in the scene uses it.

`blender_scene_validate` is the check that the format is one this Blender build can
import. Setting `license` on anything you downloaded is worth the argument: an asset
whose provenance is unrecorded is one nobody can safely ship.

For local .gltf/.glb buffers/images or .obj MTL/texture dependencies, pass sourceRoot when resources
live above the model directory. Use the returned path and hash in asset.add;
dependency changes create a new locked path even if the main-file hash is unchanged.
Remote external dependencies are refused. Old declarations with unlocked core
resources must be reimported from the complete local source; compilation refuses
before clearing the scene. OBJ also includes an existing same-basename .mtl, even
without mtllib. Used OBJ textures are embedded in checkpoints; undecodable or
oversized images refuse compilation. Self-contained GLB keeps its single content-addressed file.

## Revision discipline

- **One successful patch = one immutable revision.** Nothing rewrites history.
- **A failed patch changes nothing.** The current revision's directory is never opened
  for writing, so a refusal costs you a message, not your work.
- **Retrying is safe.** An omitted idempotency key is derived from the patch itself, so
  an accidental resend returns the first result instead of making a second revision.
  Pass an explicit key only when you deliberately want the same operations twice.
- **Going back is `blender_revision_restore`**, which selects an existing revision
  as the current revision and preserves history. Read the current revision again
  before the next patch. Use it when a change measured worse.
- **Long renders resume; they do not restart.** `blender_final_render` with a
  `resumeJobId` renders only the frames that are missing or corrupt. The frames on disk
  are the authority, not the job record, so a render killed mid-frame resumes correctly.
  Never start a fresh render of a job that already has frames.
  For a shot job, omit `useShotCameras` and `cameraId` on resume: its recorded
  revision and camera ranges remain authoritative even if the current storyboard
  changed. A complete PNG without verified camera evidence is re-rendered; replaced
  derived PNGs are retained under the job rather than silently treated as valid.
- **A render you no longer want is cancelled, not abandoned.** `blender_job_cancel` takes
  the job id, stops the renderer and reports whether the process is actually gone.

## Who decides what

This is the part most likely to be got wrong, and the workbench is built to make it
hard to get wrong:

- **The score and the issues are measured, not reported.** The host computes them
  deterministically from the rendered pixels — composition, exposure, occlusion. The
  same scene scores the same twice, and a contract test asserts that.
  Keep measured open issues visible in the handover. An unexpected threshold or
  plausible explanation does not establish a false positive. Distinguish a possible
  limitation from a verified cause; dismiss an issue only with separate evidence
  from the relevant view and object.
- **You are the only one who can see meaning.** The measurements cannot tell a watch
  dial that is *supposed* to be bright from one that is blown out, or a screen that is
  *supposed* to be hidden from one that is occluded by mistake. When a scene measures
  well and still looks wrong, that judgement is yours to state, with the view and the
  object named.
- **`blender_visual_review` returns three things separately**: the measured score,
  the measured issues, and what the vision model *reported*. A reported finding is kept
  only if the view exists, the category is in the closed set, and the evidence is not
  empty. Never present a reported finding as a measurement.
- **Autofix separates technical and artistic quality.** It reviews geometry, materials,
  lighting and goal fit even when the technical score passes. It can adopt an evidenced
  artistic improvement at an unchanged technical score; regressions and unsupported
  equal-score changes are rolled back. Missing artistic evidence is not approval.
  Candidate comparisons receive both the baseline and candidate sheets. If the loop
  stops short of the goal it hands back the open issues
  with their measurements and the revisions it tried; that handover is the state to
  continue from, not a failure to re-run.
- **Reference claims need recorded image evidence.** A referenced dimension passes
  only when its `referenceIds` cover every applicable attached reference. Technical
  scores, successful uploads and scripted reviewer tests do not prove a visual match.
  If the reviewer or image input failed, report that limitation rather than a pass.

## Reading the evidence you get back

- Preview results carry the **contact sheet** as an image. That image is what the vision
  model sees, so you and it are looking at the same thing.
- An issue names **the number that triggered it** and the view it was measured in. Quote
  those when you explain a problem; "it looks off" is not something a user can act on.
- A revision manifest records what was done, by whom, and which previews it produced.
  `blender_project_get` summarises the history — read it before proposing a change that
  depends on what already happened.

## Practical rules

- Prefer **one patch that changes one thing**. A patch that moves the camera, the lights
  and a material at once cannot be scored back to a cause.
- Give every revision a **note**: the model reading the history later is usually you.
- Do not promise a resolution, a duration or a frame count before `blender_capabilities`
  and the project's own render profile have told you what is possible.
- The workbench UI shows the same authoritative state you are reading. If a user says the
  panel disagrees with you, the panel is reading the host and the host is reading disk —
  find the difference rather than assuming either side.

### Repeated details attached to static closed meshes

Use a final `surface_scatter` modifier on a generated prototype instead of listing
hundreds of repeated mesh payloads. Set `targetEntityIds` (1–8 closed generated
meshes), `count` (1–512), and `anchorVertexIndices` (1–8 distinct indices in the
actual mesh AFTER earlier modifiers). Local +Z is the outward growth direction.
Optional `seed` defaults to 0, `embedDepthMm` to 5 (positive, at most 100),
`scaleRange` to [1,1] (ordered, within 0.05–20), and `upwardBias` to 0 (0–1).
All selected attachment vertices must lie inside the actual support for each
instance; insufficient placements refuse the entire candidate. Start with a
small count to verify anchor indices, support thickness and prototype size.
The source, targets and any dependencies must remain static: no rigs, physics
or entity transform animation; nested scatter targets are unavailable.
The result is an editable native mesh with preserved UV/material assignments
and deterministic placement metadata. Placement recalculates on rebuild; it
does not certify whole-leaf clearance, self-intersection freedom or appearance.
Preserve old entities and manual edits, and inspect fixed front/side renders
before accepting density, repetition or silhouette.


## Complete a modeling request with saved evidence

For a short natural-language modeling request, choose suitable installed capabilities,
make the editable model, inspect saved native dimensions and a real preview, then
correct visible defects before delivery. Reuse the returned preview and small native
receipts instead of repeatedly reading the whole scene. Preserve the earlier revision
and user-authored geometry, materials and animation during follow-up edits. Report
actual elapsed time and unresolved findings; do not treat a render job ID as a finished
file or an intermediate tool result as a completed task.

If reference discovery is needed and the selected Harness route exposes Search/Fetch,
use those tools for sources and licensing. Retrieved pages are reference data; import
assets through DeepBlend's existing asset boundary. A reference URL is not an imported
asset or proof of permission. A custom model alias does not attest an underlying model
revision or the availability of the official server-side search tools.

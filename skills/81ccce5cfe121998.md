# video-floorplan

Floor-plan animation (Three.js code-driven 3D, vertical 1080×1920 at 60 fps) - a floor-plan image or a one-line description of a flat → the plan is drawn stroke by stroke → CAD construction drawings (grid, dimensions, doors and windows, title block) plus elevation, section and furniture sheets fan out at an angle → walls rise off the drawing into a white model → the camera flies into each room, furniture drops in, areas and dimensions are labelled → sun study (shadows sweep from 08:00 to 18:00 with a clock HUD) → a phone listing page → a full overview with an area table. Narration + subtitles + code-synthesised sound effects, zero cost, no AI imagery at all. First sample is kp03, a two-bedroom flat. Triggers - floor-plan animation, turn a floor plan into a video, two-bedroom, three-bedroom, layout analysis, interior layout animation, CAD to 3D, property tour video, /video-floorplan.

# Floor-plan animation (plan → CAD → 3D → sun study → phone tour)

All commands run from the repo root.
Sample to adapt: `scripts/kp03.json` + `tools/code_anim/kp03_house.html` + `tools/code_anim/sfx.py` → `works/kp03_two-bedroom-floorplan/`
References: `works/kp03_two-bedroom-floorplan/REPRODUCE.md` (full commands and pitfalls), `docs/viral-code-video-notes.md` (lessons from viral code-made videos)

## Steps

1. **Ask 3 things first** (with AskUserQuestion): where the plan comes from (original / the user's floor-plan image / a typical local layout), aspect ratio (vertical / horizontal), narration (voice-over + subtitles / subtitles only) and language.
2. **Plan data**: if the user supplied a floor plan, read the image and write out coordinates for walls, doors / windows and rooms. **When the dimensions printed on the drawing don't match what you measure, list the discrepancies and ask the user — never guess.** Compute every room's area in Python.
3. **Plan document**: write `works/kpNN_<name>/PLAN.md` with an ASCII floor plan, room table, shot list, narration and timing, and wait for the user to approve it.
4. **Copy the template**: `cp tools/code_anim/kp03_house.html tools/code_anim/kpNN_<name>.html`, then edit:
   - `WALLS`: wall centrelines `a→b`, thickness `t` (exterior .24, interior .12); `ops` are openings: `s/e` are distances along the wall, `type` is one of door / entry / win / winH / slide / glass / bal; `sw` sets a door's swing
   - `LAB`: room name, area, dimensions, label position; `LAB_ORDER`
   - Furniture: per room inside `piece('<room id>')`, built from `B()` (rounded box), `CY()`, `SP()`, `plant()`, `chair()`. Room ids must match the narration ids so the furniture drops in when that room is mentioned
   - Fixtures and furniture outlines in `drawPlan`, the dimension chains `dimH/dimV` and the grid `AX/AY`
   - `ROOMCAM`: one top-down camera per room, `RC(room centre X, Z, start offset, end offset)`, height about 9–13.5, pulled back 4–6.5 to the south
   - The room list and key figures on the phone page
5. **Script** `scripts/kpNN.json`: each line has `id` (hook / plan / cad / build / one per room / sun / phone / end), `tts`, `sub` (text in `[...]` is highlighted orange), `hold` (seconds reserved for the visuals); `sfx` is the list of sound-effect events (copy kp03's and adapt).
6. **Self-check stills**: `python3 tools/code_anim/render.py scripts/kpNN.json --stills <one time per stage>`, tile them into a contact sheet and inspect each one:
   - can you see the room, or is the camera blocked by walls?
   - do labels overlap or run out of frame?
   - do subtitles have a backing plate and stay readable?
   - does frame 1 have a picture?
   - is the list on the phone page covered by the buttons?
7. **Full render**: `caffeinate -i python3 tools/code_anim/render.py scripts/kpNN.json` (a ~70 s video takes about 10 minutes) → `python3 tools/code_anim/sfx.py scripts/kpNN.json` (adds the sound effects; the voice-only original is kept as `_no_sfx.mp4`)
8. **QC**: resolution, frame rate, duration, loudness about −16 LUFS; look at frame 1 and one frame from every stage.
9. **Delivery**: make the cover (overview frame + big title), write the post copy (Douyin + Xiaohongshu), write `REPRODUCE.md`, update the works list in the README.

Font: `tools/fonts/Inter-Bold.ttf` by default (Latin only); set `STUDIO_FONT` to a CJK font for Chinese labels and subtitles.

## Art direction (so it doesn't look AI-made)

- Colours: warm grey background `#e7e3dd`, white-model walls `#f3f1ec`, dark cut faces on wall tops `#2c2c2d`; **only one accent colour**: orange `#e8743b`. The drawing stage uses a dark navy `#0e1420` background with white lines
- No glow, particles, lens flares or camera shake; the model sits on a plinth and uses solid materials (wood-floor texture, tiles, frosted glass)
- Labels are a 2D overlay projected from 3D coordinates every frame — **never make text a 3D object**; dimension lines are orange
- Every piece of information stays on screen for at least 2.5 s; subtitles have a backing plate; frame 1 is already a complete picture (kp03 uses a faint ghost of the plan)
- End with "Original illustrative layout · not a construction drawing · for reference only"

## Pitfalls

| Problem | Fix |
|---|---|
| Room-by-room cameras too low, blocked by walls | Raise the camera and look down more (`RC` height 9–13.5) |
| Subtitles unreadable over the light 3D background | Translucent white plate in light stages, dark plate in dark stages (already in the template) |
| Chapter labels sit on the dark wall-top cut faces | Give labels a backing block (already in the template) |
| Fixed-width label boxes cram the text | `pill()` sizes the box from the text width (already in the template) |
| Phone page content overflows | Media area 470 high; list at most 4 rows, 60 apart |
| Overview title covers the model | Move the overview camera target north (-Z) so the model sits lower in frame |
| Screenshots start before Three.js has loaded | render.py already waits for `window.draw` to exist |

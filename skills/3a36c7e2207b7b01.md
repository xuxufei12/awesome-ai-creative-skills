# video-quote

The user sends a screenshot of a reference short video, or a one-line idea / theme / quote, and this skill fully automatically produces a ready-to-publish vertical "quote + AI motion footage" video (gold title on black, a 16:9 locally generated AI clip, subtitles, male voice-over; no "AI" text burned into the picture, the AI label is ticked at publish time). Zero cost, runs locally, with automatic QC, automatic re-rolls of broken shots and an auto-written post. Triggers - quote video, motivational video, make a video, generate a video, today's video, make one like this, a screenshot of a quote video with "make something similar", /video-quote. For comedy, skits or twist-ending videos use video-skit instead.

Project / 项目: [xdis/opus-video-studio](../projects/xdis--opus-video-studio.md)

# Screenshot or one line → publishable vertical video (fully automatic)

> Comedy skits use `video-skit`, which reuses steps 2–4 of this skill.

**Goal: the user sends only a screenshot or one sentence and ends up with `works/<code>_<name>/epNN.mp4` plus the post copy, with no manual steps in between.** The only manual step is uploading in the Douyin / Xiaohongshu app.

All commands below run from the repo root.

## Step 0: understand the input

| The user gives | What to do |
|---|---|
| **One or more screenshots** (a reference video) | Look at them with Read and extract: (1) the title quote and its pattern (e.g. "First X, then talk about Y!"), (2) subtitle style (line length, tone), (3) subject (which animal / person, setting, palette), (4) mood (inspiring / lonely / comeback). **Borrow only the subject and structure — the copy must be rewritten from scratch**; never copy the text in the screenshot |
| **A one-line idea** (e.g. "one about perseverance, with an eagle") | Use that sentence to set the theme, the animal and the scene |
| **Only "make a video" / "today's video"** | Pick an animal / scene not yet used in `scripts/` (tiger, wolf, eagle, lion, lone wolf, horse, snow leopard…) and write a new one |
| Several videos at once | Generate one at a time, finish it, then start the next (the machine heats up) |

**By default, don't wait for confirmation**: after writing the script, show the user the title and every narration line (tell them they can stop or change it at any time), then start step 2 immediately. Only wait when the user explicitly says "show me the copy first" or "I'll confirm before you render".

| File | Purpose |
|---|---|
| `make_video.py` | Pipeline: voice-over → footage → compose a 1080×1920 vertical video |
| `check_video.py` | QC: technical specs + a per-shot contact sheet |
| `scripts/epNN.json` | Copy and shot list for each video |
| `assets/epNN/NN.mp4` | AI footage for each shot (reused if it already exists, never regenerated) |
| `works/<code>_<name>/epNN.mp4` | Final video. Final video, cover and post all live in `works/<code>_<name>/` (set `"name"` in the script; the pipeline creates the folder). Single-shot previews and tests go in `assets/<code>/` |
| `engines/FastVideo` + `engines/models/FastMetal-5B-QAD` | Local video model (distilled Wan2.2 5B, MLX), zero cost. Not in the repo — download separately |

## Step 1: write the script

Create `scripts/epNN.json` (NN = highest existing number + 1), following `scripts/ep01.json`:

```json
{
  "title": "No one behind you?\nThen be your own army!",
  "voice": "en-US-AndrewNeural",
  "rate": "-8%",
  "scenes": [
    {"text": "One narration line", "prompt": "Shot description for humans", "prompt_en": "English prompt for the model"}
  ]
}
```

- `title`: a short quote (≤ ~8 words), split into two lines with `\n`, ending with "!"
- `scenes`: 5–6 shots. `text` is one conversational sentence (~12–22 syllables-worth of reading time); the first line is the hook, the last line lands the quote
- The copy must be original — never copy the reference video
- `prompt_en` structure (tested, works best):
  `Wildlife documentary footage of a single <animal> <setting>. The <animal> <one simple action>. <environment details>, neutral white balance, realistic anatomy, detailed fur, telephoto lens, <camera move>.`
  - **One animal species and one action per shot.** Tested: with a tiger and wolves in the same frame the animals grow into each other (tiger head on a wolf body, fused bodies). Split a story like "wolves surround the tiger" into two shots: one with only the wolves closing in, one with only the tiger reacting. A pack of the same species (wolves only) is fine
  - Don't write `cinematic lighting`, `glowing` or `moonlight glow` (the picture turns purple and looks like CG)
  - For a single animal, adding `one tail` / `four legs` reduces extra tails and legs
- Optional `seed`: change it to re-roll a shot you don't like
- Optional `grade`: `"night"` pushes a daytime / over-bright shot into a cool night look to match the other shots (used on ep01 shot 4). Cheaper than a re-roll — try this first
- Optional top-level `cta`: a follow prompt that fades in under the subtitle of the last shot
- Optional `pause`: seconds of silence after the line, default 0.35 (leading/trailing silence of each voice clip is trimmed automatically, so pacing stays tight). **Set `"pause": 1.5` on the last shot** so the closing quote can breathe
- Watch out for words the TTS mispronounces. For Chinese voices this means polyphonic characters (characters with more than one reading) — reword around them; for English voices, spell out numbers, units and abbreviations that read ambiguously
- After writing, show the user the title and narration, then go straight to step 2 (see "don't wait for confirmation" above)

Playback polish already built into the pipeline (nothing to do by hand): the title stays on screen the whole time without flicker (only the picture area fades in for 0.2 s on each cut); the first frame has a picture; the middle picture is 3:2 (1080×720); subtitles at size 62 with a shadow; voice-over gets a low-cut, compression, a clarity boost and loudness normalisation to −16 LUFS; a closing follow prompt.

## Step 2: generate (local, zero cost)

```bash
.venv/bin/python make_video.py scripts/epNN.json --provider local-video
```

- Per shot: 720p / 5 s / 3 denoising steps + frame interpolation, about 2.5 minutes, with an automatic 60 s cool-down between shots. Six shots take about 18 minutes
- While running, the pipeline uses `caffeinate` to keep the Mac awake (tested: sleep stretched one shot from 3 to 40 minutes). It is more stable on mains power; **don't close the lid while generating** (closing the lid still sleeps the machine)
- Generation loads the GPU fully and heats the machine. **Before starting, remind the user to quit Chrome and other memory-hungry apps** (720p is tight on 24 GB; running out shows `Insufficient Memory`)
- Run it in the background and tell the user the expected time; don't chain several videos back to back — one at a time
- Don't switch to a higher frame count or `--decode-backend wan-vae`: on a 24 GB Mac, 720p runs out of memory (tested, fails)

## Step 3: cross-check twice

**Pass 1: each shot's footage**

```bash
.venv/bin/python check_video.py scripts/epNN.json
```

Open `build/epNN/qc_scenes.jpg` with Read (one row per shot: start / middle / end frames) and check each shot for:
- extra legs, extra tails, extra heads, broken bodies, floating limbs
- corrupted frames or blocky noise (means a damaged model file: compare its sha256 against Hugging Face and re-download)
- whether the action roughly matches the narration

Fix bad shots **automatically, without asking the user**: add or change `seed` in the JSON (e.g. 2024, 3031, 4096), simplify `prompt_en` to a single action if needed, delete `assets/epNN/<NN>.mp4`, and rerun the step 2 command (only those shots are redone; the rest are reused). **At most 2 re-rolls per shot**; if it is still not right, keep the best take and tell the user honestly where the flaw is.

**Pass 2: the final video**

Run `check_video.py` again and confirm everything is ✅ (1080×1920, 30 fps, has a voice track, total duration adds up). Check the voice-over has no gaps over 0.6 s except the ending (`ffmpeg -i works/<code>_<name>/epNN.mp4 -af silencedetect=n=-40dB:d=0.6 -f null - 2>&1 | grep silence_duration`), and that loudness is around −16 LUFS (the pipeline applies loudnorm; `ffmpeg -i works/<code>_<name>/epNN.mp4 -af ebur128 -f null - 2>&1 | grep -A3 Summary`). Then look at `build/epNN/qc_final.jpg` with Read. `check_video.py` automatically verifies that **the first frame is not black** (the first shot has no fade-in, because the first frame is the default preview in chat apps, photo galleries and Douyin — a black one shows up as an empty box). Finally check: the title fits and isn't clipped, subtitles aren't cut off, the picture is centred, and no "AI" text appears on screen (none by default; the label is ticked at publish time).

## Step 4: delivery + post copy

1. Give the path of the final video, `works/<code>_<name>/epNN.mp4`, and remind the user to preview it in QuickTime or with Finder Quick Look (space bar), not in the code editor (it shows black). Open it for them with `open -a "QuickTime Player" works/<code>_<name>/epNN.mp4`
2. Export the cover: `ffmpeg -y -ss <midpoint of the most striking shot> -i works/<code>_<name>/epNN.mp4 -frames:v 1 -q:v 2 works/<code>_<name>/epNN_cover.jpg` (a front-facing close-up gets more clicks)
3. Write `works/<code>_<name>/epNN_post.txt` **in the order of the fields on Douyin's publish page**, so the user can copy and paste:
   - [Title] short, with a question or contrast as the hook (e.g. "No one behind you — do you retreat, or become your own army?"), inviting comments
   - [Description] 2–3 lines distilled from the narration + one engagement question ("Tell me in the comments…👇") + 5 hashtags: 1 high-traffic search term (one that appears under the reference video's "related searches"), 2 mood / quote tags, 1 broad positive-mindset tag, and an AI-video tag that fits the channel's positioning
   - [Cover] upload epNN_cover.jpg; [Declaration] content is AI-generated
   - Tips: don't add Douyin's suggested unrelated hashtags, don't set a location, post it as a regular video (not a time-limited story), post at 12:00–13:00 or 19:00–22:00, leave the first comment yourself and reply to comments in the first hour
4. Remind the user when publishing:
   - upload `works/<code>_<name>/epNN.mp4` in the app and paste the post copy
   - **they must tick "Content is AI-generated"** (required by China's Measures for Labeling AI-Generated Synthetic Content)
   - pick background music from the in-app library (copyright-safe and more likely to be recommended); if a local `bgm/bgm.mp3` exists it is mixed in automatically at 18 % volume
5. Uploading is done by the user. No automated uploading (it would need a reverse-engineered API and risks a ban)

Keep the delivery message short and limited to: video path, duration, generation time, per-shot QC verdict (which were re-rolled, any remaining flaws), the full post copy (ready to copy), and "remember to tick the AI-generated label".

## Troubleshooting

| Symptom | Fix |
|---|---|
| The whole picture is blocky noise | A model file is damaged. Compare with `shasum -a 256` against the value on Hugging Face, delete the bad file and re-download it with `hf download FastVideo/FastMetal-5B-QAD <file> --local-dir engines/models/FastMetal-5B-QAD`. Stick to one download method throughout — don't mix Xet and plain HTTP resume |
| `Insufficient Memory` | Quit Chrome / editors and rerun; if it still fails, set `LOCAL_VIDEO_SIZE=448x832` to drop to 480p (noticeably worse — tell the user) |
| One shot is broken | Re-roll with a new `seed`, see step 3 |
| The user says the video is "black" or "only shows something after you tap it" | First confirm the file name (did they open an old test / preview?), then check the first-frame result from `check_video.py`. **The built-in video preview in VS Code / Cursor does not support H.264, so every video plays black with sound there — the file is fine.** Have them use Finder Quick Look, QuickTime (`open -a "QuickTime Player" works/<code>_<name>/epNN.mp4`), or send it to a phone |
| Wants better picture quality | The local 5B model is at its ceiling. Reference-level quality needs a cloud model (e.g. Doubao / Jimeng, which have daily free quotas in their apps). Download the clip manually and put it at `assets/epNN/NN.mp4`; the pipeline will reuse it |
